# План: песочница сна — для tero (исполнитель → судья)

Спека-источник: `specs/2026-10-27-dream-sandbox.md` (v3.6). **Спека главнее плана**: при расхождении — стоп и вопрос senior, не импровизация.
Репо: `meta/` (git). Исполнители и судьи **не коммитят**; senior коммитит после SHIP каждого этапа.
Язык кода, промптов, комментариев — английский; стиль — как в `h0/*.py` (короткий docstring с usage сверху, stdlib).

## Как резать работу

Шаги 1–5 спеки — это три отдельных tero-цикла, по очереди, каждый со своим SHIP и коммитом. Следующий не начинается, пока прошлый не принят.

| Цикл | Шаги спеки | Что получаем | Платные вызовы |
|---|---|---|---|
| **A. Движок** | 1, 3 (+ офлайн-часть 2) | память, директор, автомат сборки, лестница, ввод — всё на фейковых LLM, `--speed` | нет |
| **B. Реальные модели и медиа** | 2, 4 | живой Wonder/Spark, «иголка», Muse Image, Fish, `voices.json` | да, ≤ $3 на цикл |
| **C. Сервер и комикс** | 5 | `server.py`, `comic.html`, живой режим и повтор | да, один короткий живой прогон ≤ $2 |

Шаги 6–7 (честность H18 и просмотр пользователем) делает senior после C.

## Общие правила для всех циклов

- **Писать можно только** в `h0/dream/**` и `h0/out/dream/**`. Всё остальное только читать. Импортировать из `h0/gate_test.py`, `h0/hint_test.py`, `h0/load_test.py`, `h0/h13_sky.py` можно, но **лениво** (внутри функций): эти модули при импорте читают `os.environ["META_MODEL_API_KEY"]` (`gate_test.py:19`, `h13_sky.py:22`), а офлайн-тесты должны работать без ключа.
- `chat()` из `gate_test.py` **не использовать** (там `max_tokens=120` для Губки Боба). Все LLM-вызовы идут только через `h0/dream/llm.py`.
- Ключи: Meta берётся из env `META_MODEL_API_KEY`; Fish — из env `FISH_AUDIO_API_KEY`, иначе через `fish_key()` из `gate_test.py:125`. Ключ никогда не печатается и не пишется в лог, HTML или ответы сервера. Судья проверяет это grep-ом по `h0/out/dream`.
- Только stdlib + `numpy`/`PIL` + `aiohttp` (уже стоит). Новых pip-зависимостей нет, npm нет.
- Тесты: `cd h0/dream && python3 -m unittest -q`. Офлайн, без сети, ≤ 60 с на весь набор.
- Часы: везде `time.monotonic()` через один объект `Clock(speed)`. Ни один модуль не вызывает `time.sleep` напрямую, только через `clock.sleep()`. От этого зависит `--speed`.
- Неоднозначность в спеке → стоп и вопрос, а не своё решение.

## Цикл A — движок на фейках

**Итог:** `python3 h0/dream/sim.py --profile A --fake --speed 20` проходит ≥ 2 перехода за ≤ 90 с wall-clock и пишет корректный `log.jsonl`. Все правила автомата из спеки §4–§5a покрыты тестами.

**Файлы:** `llm.py`, `memory.py`, `director.py`, `sim.py`, `fake.py` (фейковые LLM, Fish и Image), `profiles/{A,B,C}.json`, `scenes/start.json`, `test_memory.py`, `test_director.py`, `test_sim.py`.

**Интерфейсы.** Это рекомендация; если меняешь, запиши в отчёт.
- `llm.call(role, system, messages, max_tokens) -> Reply(text, usage, seconds, dollars)`. Роли: `hero`, `actor`, `director`, `shadow`, `compress`, `judge`. Модель и effort выбираются по роли, правила из спеки §6 зашиты внутри. `Fake` подставляется через один флаг `--fake` или аргумент.
- `Memory(budget).add_line(...)`, `.add_event(...)`, `.apply_facts(updates)`, `.record_decision(...)`, `.build_prompt(state) -> (text, sizes)` — синхронно, без LLM; `.compact_async()` — фоновое слияние.
- `Director.consult(memory, state) -> Decision | Stale | Fail` с проверками из спеки §8.
- `BuildFSM` — отдельный класс, без LLM и без I/O, все переходы из спеки §4. Его тестировать в первую очередь.
- `sanitize(text, speaker)`, `resolve_touch(value, objects)` — чистые функции.

**Профили и стартовая сцена:** 3 профиля по спеке §12. У каждого есть `hero_voice` и хотя бы один факт `hidden_from_hero`. `scenes/start.json` — гостиная Сквидварда, ≥ 8 предметов с зацепками под A, B и C (спека §9).

**Проверка (судья запускает сам):**
1. `cd h0/dream && python3 -m unittest -q` → `OK`, число тестов в выводе. Обязательные тест-кейсы (по одному или больше на каждый пункт):
   - память: 300 реплик + 10 переходов + затор 50 событий → каждый `build_prompt` ≤ 5800 ток (`ceil(chars/3.5)`); ядро есть в каждом промпте; слияние идёт из `episodes_raw/`, а не из сводки сводок; `budget_trim` без LLM;
   - автомат: все пункты спеки §4 списком — `TOUCH` в `building`/`ready`, L4 на 20 с, `auto_touch` на 40 с, отмена таймеров при `abort_build`, `build_epoch` → `consult_stale` отбрасывает всё, `pending_wakeup`, запертый блок цели → `invalid`, > 2 abort → `wake_up("abort_loop")`, 3 `director_fail` → `wake_up("director_stuck")`, серия сбрасывается, `fail` до 5:00 не считается;
   - подсказка и требование: событие на 2:00 и 5:00, `min_interval` 20 с, требование его не ждёт, метки `free/nudged/forced` + `nudged_before`;
   - ввод: `sanitize` для `human` и `actor` (инжект `[[TOUCH:clarinet]]`, `[WORLD …]`, `door_ready=1` не доходит ни до одного промпта); `resolve_touch` на предметах стартовой сцены (точное совпадение, по слову, мн. число, `touch_ambiguous`, `touch_rejected`); реплика человека выкидывает заготовленную реплику NPC (`turn_replace`); событие `{"source":"dart","outcome":"missed"}` попадает в следующую консультацию;
   - лестница: на L0–L1 актёр (фейк, который «хочет» назвать мост) не называет мост — значит, его выход отфильтрован или ассерт падает;
   - время: окно `420/N ≤ t_ready − t_build_start ≤ 420/N + 2`; стресс «директор отвечает 8 с при `--speed 20`» + случайные `TOUCH` → ≥ 1 `consult_stale`, 0 смен моста в `building`, 0 исключений.
2. `python3 h0/dream/sim.py --profile A --fake --speed 20 --max-transitions 2` → exit 0; в `log.jsonl` ≥ 2 события `transition`; у всех событий `seq` растёт строго по 1; каждый `bridge` из `transition` есть в `objects` своей сцены; ни одного `bridge`, который подставил код.
3. Grep: в `h0/dream` нет `time.sleep(` вне `Clock`; нет `from gate_test import chat`; нет импортов ключевых модулей на верхнем уровне.

**Ловушки:** фейковый директор должен уметь отвечать: «пока рано» (`null`), битым JSON, мостом не из сцены, `abort_build` и с задержкой. Иначе ветки автомата останутся без теста. `--max-transitions` нужен только для тестов, в спеке его нет, R10 он не нарушает.

## Цикл B — реальные модели, картинки, голос

**Итог:** на живых Wonder/Spark директор проходит проверки спеки §15 шаг 2. `images.py` и `voice.py` работают, у каждого есть запасной путь. Короткий живой прогон без браузера, с голосом и картинками, проходит хотя бы 1 переход.

**Файлы:** `images.py`, `voice.py`, `voices.json`, `test_media.py`, правки в `llm.py` (таблица цен с источником и датой), `director_live_check.py` (скрипт шага 2).

**Проверка:**
1. `python3 h0/dream/director_live_check.py` → для каждого из 3 профилей: JSON валиден, мост из сцены, `why` ссылается на душу. **Иголка:** факт из первых минут, который понадобится на 3-м переходе (срез памяти заморожен), директор использует. **Ловушка:** если предложить тот же мост второй раз, директор его не повторяет. Плюс сверка `ceil(chars/3.5)` с `usage.prompt_tokens`: расхождение и, если нужно, новый коэффициент. Цена ≤ $1, вывод сохраняется в `h0/out/dream/checks/director.json`.
2. `voices.json`: 6 меток из спеки §6, по каждой `reference_id` из библиотеки Fish и сэмпл `h0/out/dream/checks/voices/<метка>.wav`. Senior прослушивает их до цикла C.
3. `python3 -m unittest -q` — всё зелёное, новые тесты офлайн. Длина wav считается из заголовка; при таймауте или 429 Fish реплика идёт без звука с паузой по тексту (`tts_fail`); при падении картинки — запасной фон или силуэт, сон не стоит.
4. `python3 h0/dream/sim.py --profile A --speed 4 --max-transitions 1 --max-dollars 2` → exit 0; все файлы из лога (аудио, картинки) есть на диске; у каждой реплики `dur` совпадает с длиной wav ± 0.05 с; `cost` в логе не больше $2.

**Ловушки:** Muse Image иногда отдаёт 400 — 3 ретрая, как в `h13_sky.py gen()` (`:41`). Fish отдаёт 429 на всплески — ретраи как в `load_test.py:68`. Не больше 2 картинок одновременно.

## Цикл C — сервер и комикс

**Итог:** пользователь открывает страницу и смотрит живой сон, как в спеке §11. Видно решения директора и его записки, таймер, переходы; работают «сказать за героя», клик по предмету и «стоп». Тот же HTML воспроизводит готовый лог.

**Файлы:** `server.py`, `comic.html`, `test_server.py`.

**Проверка:**
1. `python3 -m unittest -q` — зелёное, включая `test_server.py`:
   - запрос с чужим `Origin` или `Host` → 403;
   - POST не `application/json` → 415 или 400;
   - `/events?from_seq=N` отдаёт события начиная с N;
   - `/say` и `/event` проходят `sanitize`.
2. Живой прогон: `python3 h0/dream/sim.py --profile A --speed 4 --serve` + браузер (Playwright MCP или Chrome):
   - консоль без ошибок;
   - скриншоты в `h0/out/dream/<run>/shots/`: реплика с ремаркой, карточка «Директор думает» (слои памяти, выбор, ✓/✗, метка, секунды), пунктирная записка директора актёру, таймер сборки со статусом картинок, панель перехода;
   - «сказать за героя» доходит до лога как `turn_owner: human`;
   - клик по предмету даёт `TOUCH` или `stall`;
   - «стоп» завершает сон (`stop` в логе, процесс выходит с кодом 0).
3. Повтор: `comic.html?run=<run>` без живого сервера-симулятора открывает готовый лог; прыжок к сцене 2 работает; режим «мгновенно» проигрывает весь лог без звука.
4. Grep: ключа нет ни в ответах сервера, ни в HTML, ни в `h0/out/dream`.

**Ловушки:** SSE после переподключения должен продолжать с `from_seq` и не терять события; `snapshot` приходит каждые 30 с. В браузер не уходит ничего, кроме событий лога и файлов из `h0/out/dream/<run>/`. Отдачу статики ограничить этой папкой и `comic.html`, path traversal → 404.

## Что делает senior между циклами

1. Перед каждым судьёй — conformance: `git status` + полный diff. Изменения только в разрешённых путях, никаких правок в чужих файлах.
2. После SHIP — commit (коротко, lowercase, без атрибуции) и строчки в `PROGRESS.md` и `DEVLOG.md`.
3. Деньги: перед циклами B и C — `--max-dollars` в командах проверки. Если потратили больше плана, стоп и сказать пользователю.
4. Run note: `~/.claude/tero/runs/2026-10-27-dream-sandbox.md` — контракт каждого цикла, попытки и вердикты дописываются, старое не переписывается.
