### Контракт моста (общий для полос A и B; менять только в обеих полосах сразу, через хозяина)

Полоса A пишет мост, полоса B его зовёт. До слияния полоса B моста не видит и тестирует себя на заглушке, поэтому контракт зафиксирован здесь, а не выводится из кода.

- **Файл и запуск.** Мост — `engine/bin/moves.ts`, запуск `node --import tsx bin/moves.ts …` с `cwd = engine/`, так же запускается `clipfacts` (`h0/make/cast.py:399`). В спеке мост назван `moves.mjs`, но `.mjs` без загрузчика `tsx` не импортирует исходники TS; во всём остальном действует спека.
- **`--catalog`** печатает в stdout JSON `{"styles": [id…], "moves": {id: "смысл одной строкой"}, "schemes": {…}, "records": {…}}`, ключи — ID из `STYLES`, `MOVES`, `SCHEMES`, `RECORDS`. Отсюда Python берёт список для промпта Spark, проверку имён (`MOVE_UNKNOWN`) и проверку `camera_style` (`STYLE_UNKNOWN`). Своего списка ID в Python нет.
- **`<in.json> <out.json>`**, один вызов на сцену. Вход:
  - `style`;
  - `room` в формате `DRoom` (`{outline, ceiling, open, floorY?}`, `director.ts:38`);
  - `obstacles`: `[{min:[x,y,z], max:[x,y,z]}]`;
  - `actors_by_beat`: `{"<beat>": DActor[]}`;
  - `beats: [{beat, move: string | null, subject: {actor} | {pair} | {room: true} | null, at, to, hold?: bool, tags?: {first?, enter?, look?, last?}}]`;
  - `fov`, `aspect`, `seed`.
- **Что делает мост с битом:**
  - `move: null` → `pickMove(STYLES[style], tags, rng)` с `rng` из `seed` (тот же генератор, что в тестах К2);
  - `subject: null` → говорящий бита, а если в бите нет актёров — `{room: true}` и `wide`;
  - ID из `SCHEMES` → `planScheme`;
  - ID из `RECORDS` → статичная точка и строка в `records`;
  - `hold` правит время по К3.
- **Выход:** `{"shots": [план Г8…], "records": [{beat, move, subject}], "warnings": ["MOVE_… B<i>", …]}`. Планы с `MOVE_NO_LEGAL_POINT` и `MOVE_OCCLUDED` в `shots` не пишутся (fail closed), их предупреждения с номером бита идут в `warnings`.
- **Ошибка:** код выхода ≠ 0 или битый JSON в `out.json` → в Python `SHOTPLAN_BRIDGE <текст>`, стадия `ok` без `plan.json`.
- **`plan.json` собирает Python:** `{version: 1, scene, world, shots, notes}`, где `notes` — одна строка `json.dumps({style, records, warnings})`. Рантайм (полоса A) читает из неё `style`.
- **Проверка после слияния** (её пишет полоса B): тест `test_bridge_real` в `h0/make/test_shotplan.py` пропускается, пока нет `engine/bin/moves.ts`. Когда мост появился, тест гоняет настоящий мост на фикстуре полосы B (`h0/make/testdata/moves_bridge/in.json`, спальня Кошакана, 3 бита) и `--catalog`, затем сверяет ключи с `h0/make/testdata/moves_bridge/catalog.json`.

### Судья, фьюз, долг

- **Судья.** Блокер — это красный тест или нарушение явного пункта фазы, в том числе запись вне территории полосы. Крайний случай, которого нет в пунктах, идёт в долг как minor. Требование «сделать то, чего нет в плане» находкой не считается.
- **Фьюз.** Если за 6 раундов нет SHIP, хозяин дословно переносит остаток в `specs/make-debt.md` (раздел «Камера, полоса B») и ставит `[x]` у чекбоксов фазы. Галочка при долге не значит «сделано».
- **Нет входа фазы.** Фаза пишет `BLOCKED: <чего нет>` в тот же раздел и свою часть не делает.

**Зачем.** Фильм Кошакана (спальня, круг 6) хозяин оценил на 6/10: камера законная, но «закреплённая». В плане одна точка на всю длительность, а общий план прибит к месту (`0803ed6`). В ручном демо Sonnet (`anymove/runs/koshakan/demo/story.js`) каждый план — это движение от `from` к `end`:
- наезд или отъезд на 0,2–0,6 м;
- угол обзора меняется на 4–8°;
- лёгкая тряска 0,002–0,006 м;
- взгляд на кость головы.

Исполнитель такого плана в движке уже есть (`engine/src/runtime/stage/shotplan.ts`, Г8, `60c64f4`). Не хватает того, кто пишет план. Г9 (`specs/2026-11-02-film-eyes.md`, Spark пишет сырые координаты) хозяин остановил и не начинал. Опыт L144 показал, что Spark с сырыми координатами снимает затылки: 4 кадра из 9.

**Решение.** Spark не пишет координаты. Он выбирает на каждый бит **приём** из закрытого списка и **субъекта**, а стиль режиссёра задаёт веса и ритм. Код превращает приём в точки `from`/`end` по измеренным фактам: голова, лицо (`faceYaw`), поза, стены, правило 180°. Результат — обычный `shotplan/plan.json` формата Г8. Так у нас вкус модели и гарантии кода.

**Гибкость (требование хозяина).** Всё переопределяется сверху вниз:
- `plan.edited.json` руками, если есть;
- выбор Spark на бит;
- стиль сцены;
- стиль по умолчанию;
- правила `director.ts`, если плана нет совсем.

Новые приёмы и стили — это строки данных, а не код в режиссёре.

Эта спека **заменяет Г9** в `specs/2026-11-02-film-eyes.md`. Г10 (петля правки по листу кадров) остаётся на потом.

### Каталог приёмов (исследование, вход фазы К1)

Источники:
- глоссарии движений камеры: [NFI](https://www.nfi.edu/camera-movement-terms), [MasterClass](https://masterclass.com/articles/guide-to-camera-moves), [Berkeley](https://casn.berkeley.edu/wp-content/uploads/resource_files/CameraMovementterms.pdf), [Morphic, 44 движения](https://morphic.com/fr/resources/shots/camera-movements);
- о стилях: [Bordwell об Андерсоне и Одзу](https://www.davidbordwell.net/blog/category/directors-anderson-wes/page/4/), [Kogonada о симметрии Андерсона](https://www.openculture.com/2014/03/the-perfect-symmetry-of-wes-andersons-movies.html);
- демо Sonnet `story.js`.

**Три группы.** Каталог — исследование; в коде у него три разных контракта:
- **атомы** (1–39 без 13, 36): один план, `resolveMove` возвращает `from` и `end`. У каждого атома машинный ID латиницей в `MOVES` (`wide`, `medium`, `close`, `push_in`, `pull_out`, `slow_push`, `truck`, `arc`, `pedestal_up`, `crane_up`, `follow_side`, `follow_behind`, `lead`, `drift`, `handheld`, `steadicam`, `zoom_in`, `zoom_out`, `dolly_zoom`, `pan_to`, `tilt_up`, `whip_pan`, `low`, `high`, `child_eye`, `tatami`, `top_down`, `profile`, `three_quarter`, `frontal`, `master`, `detail` …); остальное — по тому же образцу `snake_case`, полный список — в `MOVES`. Русские имена каталога — алиасы в `MOVES[id].aliases`; Spark получает ID с одной строкой смысла и отвечает ID;
- **схемы** (40–42, 46–50): последовательности атомов по битам, отдельный реестр `SCHEMES` с ID: `over_the_shoulder` (40), `reaction_cut` (41), `establishing` (42), `oner` (46), `rhythm_cut` (47), `return_wide` (48), `open_from_light` (49), `final_pull_out` (50). Их раскладывает не `resolveMove`, а `planScheme(id, beats: SchemeBeat[], ctx) -> [{beat, move, subject, at, to}]`, где `at`/`to` — `B<i>`/`B<i>e` (формат Г8); у `oner` `to` плана n равен `at` плана n+1, а `from` n+1 строится от `end` n; обрыв цепочки (смена комнаты, пропущенный бит, нет субъекта) начинает цепочку заново с новой свежей точки в `moves.ts`, где `SchemeBeat = {i, kind: "line"|"narrator"|"walk", speaker?, listener?, about?, actors: string[], durationS, tags}`. Fallback: один актёр в кадре — вместо восьмёрки `close` на него; нет субъекта — `wide`; другая комната — схема обрывается и следующий бит начинает заново; `insert` и `pov` в первой версии — записи без исполнения (`MOVE_RECORD_ONLY`: нужна кость руки или предмет); результат идёт в `resolveMove` по плану. Схема — это правило выбора атома на бит (восьмёрка = `ots` на говорящего, потом на слушающего; `oner` = цепочка атомов, где `to` предыдущего плана = `at` следующего, а `from` следующего = `end` предыдущего; `final_pull_out` = `pull_out` на последнем бите);
- **записи без исполнения** (13 `dutch`, 36 `rack_focus`, 43 `insert`, 44 `pov`, 45 `cross_cut`; `insert` и `pov` в первой версии без предметов и внутреннего вида — записи; они входят в `RECORDS`, третий реестр, который Spark может назвать, а `pickMove` не выбирает): `resolveMove` возвращает статичную точку той же крупности и предупреждение `MOVE_RECORD_ONLY <id>`; запись пишется в `notes` — **одна** строка `JSON.stringify({style, records: [{beat, move, subject}], warnings: [...]})` (тип `Shotplan.notes` в `shotplan.ts` — строка, `parseShotplan` не меняется; рантайм разбирает её сам, `try/catch`, битая или без полей → стиль из параметра запуска); тест round-trip: Python пишет, `index.ts` читает те же поля; запись не попадает в `shots[i]`.

Каждый атом задаётся относительно субъекта (кость головы или середина пары) через параметры:

| Параметр | Что это |
|---|---|
| размер | доля высоты кадра, которую занимает субъект |
| азимут | угол от линии лица |
| высота | метры над полом или доля роста |
| движение | изменение азимута, дистанции, высоты и fov от `from` к `end` |
| ease | кривая движения |
| shake | тряска |

**Крупность** (задаёт дистанцию по fov):

2. средне-общий;
3. средний;
4. средне-крупный;
5. крупный;
6. деталь (кость руки или предмет);
7. мастер-план (вся комната).

**Ракурс:**

**Поворот без смещения:**

38. вертикальная панорама (взгляд снизу вверх по фигуре);

**Схемы монтажа** (несколько планов подряд):

41. перебивка-реакция (крупный слушателя);
42. установочный план (общий в начале сцены);
43. вставка (деталь предмета из текста);
44. точка зрения (камера из головы актёра);
45. перекрёстный монтаж двух мест (позже, нужны две комнаты);
46. длинный план без склейки (oner): цепочка движений одним планом;

### Стили (вход фазы К2)

Стиль — это строка данных:
- `weights` — вес приёма;
- `asl` — средняя длина плана, с;
- `height` — смещение высоты;
- `fov` — диапазон;
- `shake` — диапазон;
- `move` — доля планов с движением;
- `cut` — склейка или длинный план;
- `symmetry` — лобовой центр.

Стартовый набор:
- `storybook` (по умолчанию, Кошакан): мягкие наезды, камера на уровне ребёнка, пауза на лице, ASL ~5 с;
- `spielberg`: медленные наезды на эмоции, oner с движением, низкий ракурс на героя;
- `ozu`: татами, без движения, лобовой средний, ASL ~7 с, склейки строгие;
- `anderson`: лобовой центр, симметрия, проезды вбок, панорамы 90°;
- `malick`: широкий fov, плавающая ручная камера, вставки на окно и свет;
- `fincher`: точное медленное движение без тряски, чуть ниже глаз, короткие склейки на реплике;
- `kubrick`: центральная перспектива, медленный наезд по оси;
- `miyazaki`: долгие планы покоя, отъезд к окну, деталь природы между репликами.

Значения `cut` по стилям: `storybook` hard, `spielberg` long, `ozu` long, `anderson` hard, `malick` long, `fincher` hard, `kubrick` long, `miyazaki` long. В `ozu` реплика нового говорящего внутри пары план не режет (его `asl` 6–8 с держится); тест: два говорящих чередуются по 3 с → один план на ≥ 6 с.

Типы полей стиля (`styles.ts`, `Style`):
- `weights: Record<StyleId, number>`, `StyleId` = ID из `MOVES` или `SCHEMES`; вес ≥ 0; ID вне `MOVES` в таблице — ошибка загрузки (тест);
- `asl: [min, max]` секунд — желаемая длина плана при выборе `hold` и ритма; не ограничивает реплику (план длится бит);
- `height: [min, max]` метров камеры над полом комнаты (при выборе высоты — пожелание `ceiling − 0.3`; жёсткий предел рантайма `ceiling − 0.1` из `legalCameraPoint`, тест проверяет оба: выбор ≤ `ceiling − 0.3`, итог ≤ `ceiling − 0.1`);
- `fov: [min, max]` градусов вертикальный;
- `shake: [min, max]` метров;
- `move: number` 0..1 — доля планов с `end`;
- `cut: "hard" | "long"`;
- `symmetry: number` 0..1 — **предпочтение** фронтальных планов (не гарантированная доля): при ≥ 0,6 веса не-фронтальных кандидатов ×¼ (`pickMove`, шаг 2). Тест проверяет только угол у планов, помеченных `frontal`/`tatami`.

Таблица раскладки схем в режиссёре (ниже) — исчерпывающая.

**Три реестра:** `MOVES`, `SCHEMES`, `RECORDS` (`dutch`, `rack_focus`, `insert`, `pov`, `cross_cut`). **Два основных реестра.** `MOVES` — атомы (`resolveMove` принимает `MOVES ∪ RECORDS` (запись возвращает статичную точку и `MOVE_RECORD_ONLY`)), `SCHEMES` — `over_the_shoulder`, `reaction_cut`, `establishing`, `return_wide`, `oner`, `final_pull_out`, `rhythm_cut`, `open_from_light` (`planScheme` принимает только их). Spark, `weights` и `pickMove` оперируют объединением; при разборе ID, найденный в `SCHEMES`, раскладывается `planScheme` (мост) или в атом по таблице ниже (режиссёр); один и тот же ID не живёт в обоих реестрах (тест на пересечение).

**Схемы в режиссёре.** Режиссёр не заглядывает вперёд (он событийный), поэтому в нём ID схемы работает как атом на один бит: `over_the_shoulder` → `ots` на говорящего; `reaction_cut` → `close` на слушающего; `establishing` и `return_wide` → `master`; `final_pull_out` → `pull_out`. `oner`, `rhythm_cut`, `open_from_light` исполняет только мост (`planScheme` на списке битов), в режиссёре их вес считается 0 (тест).

**Выбор приёма** — одна функция `pickMove(style, tags, rng) -> {id, warnings}` в `styles.ts` (мост зовёт её же для `--fake`). Порядок шагов фиксирован, без повторных жеребьёвок:
1. **Принуждение тегом.** Если есть тег, ID берётся по приоритету `last` (`final_pull_out`) > `first` (`establishing`) > `enter` (`follow_side`, а в комнате без прогулки — `crane_down`) > `look` (`over_the_shoulder`). Принуждённый ID, несовместимый со стилем (`style.move == 0` и он `moving`; на реплике — `follow_behind`/`lead`), заменяется `staticOf(id)` (веса не применяются, жребия нет); результат возвращается сразу, `warnings` содержит `TAG_STATIC <id>`.
2. **Кандидаты.** ID из `weights` с весом > 0, из них убраны несовместимые: при `style.move == 0` все `moving`, на реплике `follow_behind`/`lead`, схемы `oner`/`rhythm_cut`/`open_from_light` (их исполняет только мост). В стилях с `symmetry ≥ 0,6` кандидаты кроме `frontal`/`tatami`/`master`/`medium` весят вчетверо меньше.
3. **Жребий `moving`.** `rng() < style.move` → пул = `moving`-кандидаты, иначе статичные; пул пуст → другой пул; оба пусты → `wide`.
4. **Взвешенный жребий.** Накопленная сумма весов в порядке записи в `weights`; `rng() * сумма` выбирает ID. Контрактные тесты фиксируют `rng ≡ 0` (первый ID пула) и `rng ≡ 0,999` (последний).
5. `hold` в `pickMove` не участвует (см. К3).

**Правило склейки и ASL.** Режиссёр режет план (`cut` +1) на новой реплике, смене бита, прогулке, смене комнаты. Исключение `cut: "long"`: план с субъектом `pair` не режется ни репликой, ни сменой `beat`, пока говорящие чередуются внутри пары, пока не прошло `asl.max` секунд. `cut: "hard"` режет всегда. Событие `tick` не выбирает приём и план не режет (исключение — поворот лица, К2). Максимум без движения: план без `end` длиннее `2·asl.max` секунд (длинная реплика, прогулка) получает `drift` (0,1 м), кроме стилей с `move == 0`. `asl` — мягкая цель; ASL в тесте = среднее расстояние между соседними `cut` по сумме `dt` событий, **тест подаёт по одному событию на шаг** (в `index.ts` при нескольких событиях за кадр `dt = 0` у всех, кроме последнего, `index.ts:828–836`), последний незакрытый план не считается.

**Конфликт высоты.** Диапазон `height` стиля — пожелание; последнее слово у `legalCameraPoint` (`[floorY + 0.3, ceiling − 0.1]`, при пустом диапазоне в низкой комнате побеждает нижняя граница), допуск тестов 1 мм. Тест «высота в диапазоне стиля» сравнивает с **пересечением** диапазона стиля и `[floorY + 0.3, ceiling − 0.1]` комнаты; пересечение пусто — проверяется только граница комнаты.
