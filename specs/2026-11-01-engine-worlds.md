## Н1. engine: меш режется под бюджет при сборке

Зоны: `engine/src/assets/cut.ts` (новый), место в `engine/src/build/**`, где `build` берёт GLB предмета из кэша (`assetFiles`, `props.ts`, `write.ts`), `engine/test/asset-cut.test.ts` (новый), `h0/pipe2/assets.py`, `h0/pipe2/keys.ts`, их тесты.

Правило хозяина: меш генерируется в полном качестве и лежит в кэше нетронутым; бюджет применяется при сборке, «деградировать только чтобы уместиться». Поэтому ключ кэша `tris` не содержит (`cacheKey` не меняется) и один и тот же меш можно резать по-разному в разных сценах.

Контракт `cutGlb(buf: Buffer, tris: number): Buffer`:
- вход GLB с индексированными треугольниками (режим 4); текстуры, материалы и UV сохраняются как есть;
- если треугольников уже ≤ `tris`, возвращается тот же `buf` (побайтно);
- иначе вершинная кластеризация: размер ячейки сетки подбирается бисекцией по bbox так, чтобы результат был ≤ `tris` (запас 0.9: цель `floor(tris × 0.9)`); в ячейке остаётся одна вершина (средняя позиция, нормаль и UV первой по индексу); вырожденные и дублирующиеся треугольники убираются;
- детерминизм: два вызова дают одни и те же байты;
- результат не пустой: если кластеризация не оставила ни одного треугольника, ошибка `CUT_EMPTY` (не пустой GLB).

`build`: для каждого ассета объекта берётся жёсткий лимит из `TRI_LIMITS[propClass(size)]` самого строгого пропа, что его использует (как это уже считает `h0/pipe2/keys.ts`); если меш в кэше больше лимита, в сборку идёт `cutGlb(...)`, а в `build.json` у ассета появляется `cut: {from, to}`. Кэш не меняется. После сборки `check --built` по бюджету зелёный.

Мёртвая обвязка бюджета на стороне pipe2 (она кормила удалённый Trellis) убирается: `tris` в строках `keys.ts`, параметр `faces` у `ModalMesh.submit`, `SIZED_APPS`, запись `<key>.full.glb` в `AssetQueue`. Тесты, что их проверяли (`test_assets.py`, `test_engine.py`, `test_world_engine_fixture.py`), переписать под новый контракт; смысл тестов сохранить.

## Н2. engine: объект по картинке-референсу

Зоны: `engine/src/assets/**`, `engine/schema/**`, `engine/src/check.ts`, `h0/pipe2/floor.py`, `h0/pipe2/assets.py`, `h0/pipe2/fakes.py`, их тесты, новые `engine/test/asset-ref.test.ts` и `h0/pipe2/test_ref_assets.py`.

Это главный провал миров Кошакана: ассет `object` рисуется только из текста (`cacheKey` = хеш промпта), архитектор видит картинку места, а в генерацию предмета уходит лишь пересказ — кровать «по описанию», не та, что на картинке. Ручная проверка 01.11 (`pic_bedroom.py`): предмет вырезается из картинки места и перерисовывается целиком на белом → SAM3D → спальня узнаваема.

Контракт:
- у записи ассета (`object`, `decal`, `tile`) необязательное поле `ref: {image: string, what: string}`; `image` — путь относительно папки сцены, `what` — что на картинке вырезать (например «кровать у левой стены»);
- `cacheKey(kind, prompt, aspect, ref?)`: без `ref` ключ побайтно прежний (тест на зафиксированном известном ключе), с `ref` в хеш входит sha256 байтов картинки и `what`;
- провайдер картинок получает `ref?: {bytes, what}`; фейковый провайдер запоминает байты (тест их читает); провайдер, который `ref` не поддерживает (сегодня живой Muse Image), рисует по тексту и пишет в отчёт `REF_IGNORED` с id ассета, молча не игнорирует;
- `check`: `ref.image` не найден → ошибка `REF_MISSING` с id ассета;
- pipe2 `floor.py`: у каждого `object`, для которого у комнаты есть референс-кадр (`refs/<комната>.*` в плане), `ref.image` указывает на этот кадр, `ref.what` — имя предмета из сцены. Живой адаптер «вырезать и перерисовать» (GPT) в эту ночь не пишется: интерфейс, ключ, проверка, отчёт.

## Н3. камера: решения по противоречиям и долг А3a/А3b

Зоны: `engine/src/runtime/stage/director.ts`, `engine/src/runtime/stage/index.ts` (только обработка камеры и очереди реакций), `engine/src/runtime/stage/camera.ts` (только добавлять), `engine/test/stage-director*.test.ts` (расширять), новый `engine/test/stage-director-debt.test.ts`.

Контракт камеры — прежний (правило 180° по оси от меньшего имени к большему, клип `close`/`ots` от роста, внутри комнаты через `clampCamera` + `snapInside`). Судья прошлой ночи нашёл в нём противоречия; здесь они решены (решения хозяина по умолчанию):

1. Сторона по правилу 180° сильнее конуса лица. `close`/`ots` выбирают на нужной стороне точку с наименьшим углом к лицу; если ≤ 60° достижимо вместе со стороной — берётся такая; если нет — остаётся лучшая на нужной стороне (угол > 60° допустим).
2. Точка, лежащая на оси (|скалярное произведение с нормалью| < 1e-6), стороной не считается: сдвигается на нужную сторону.
3. `place` после `snapInside` перепроверяет сторону; если точка перешла на чужую, берётся ближайшая внутренняя точка нужной стороны, иначе запасной кадр.
4. Явный `shot` из банка берётся как есть, в том числе `orbit` и `dolly` для одного актёра. Ограничение «одному актёру — `wide`/`close`/`follow`» действует только на случайный выбор.
5. Если пул случайного выбора свёлся к одному плану, он может повторить предыдущий (как правило 4 рассказчика).
6. Сглаживание положения камеры (`1 − e^{−4·dt}`) держит промежуточную позицию внутри контура текущей комнаты (`snapInside`); в L-комнате она не уходит в вырез.
7. Очередь реакций сбрасывает только новая реплика; смена набора идущих актёров её не трогает.
8. Для актёров ближе 0.3 м ось берётся по взгляду говорящего в момент начала реплики и хранится до конца реплики (реакция на 45 % её не меняет).
9. Высота камеры без актёров не больше `потолок − 0.1` и не меньше 0.3 м.
10. Запасной кадр: в комнате, где нет точки с отступом 0.3 м, берётся центр комнаты, а не первая точка внутри контура.
