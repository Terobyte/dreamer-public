# Движок сцен: SCENE.json → мир

Черновик v0.7, 2026-10-28. Статус: после 4-го раунда критики и 3-х волн «спека + план» (числа и все сломанные сцены прогнаны исполняемым оракулом). По ней идут планы `tero-engine-phase1.md` (сдан) и `tero-engine-phase2.md` (фазы 2–5). v0.7 вносит в спеку решения, о которых v0.6 молчала (правило id, свободные стены и `fixtures` в геометрии, ступени и перекрытие, маршруты, разница отчётов, `top.png`): план на них ссылается, а не решает сам.

## Стек и где лежит код

- **TypeScript, Node 22.** Компилятор и рантайм на одном языке: `floorAt`, коллизия и линтер — общий код для `check` и страницы.
- Код: `engine/` в корне репо (пока в `meta-world`, после прогона tero — в `meta`). Модули `src/{schema,geom,plan,openings,stairs,props,decals,cameras,nav,report,build}`, CLI `engine/bin/dreamer.ts` (`npx tsx bin/dreamer.ts check|build ...`).
- Библиотеки: `clipper2-ts@2.0.1` (`Clipper.inflatePaths`, offset + union для тела стен и навигации; дуги дискретизируются до буфера; `clipper2-js` 1.2.4 не годится — offset неверный и состояние течёт между вызовами), `ajv` (схема), `three` (вывод), `playwright` (`top.png`, лист, маршруты в браузере), `vitest` (тесты, `npm test`).
- Допуски: геометрический `eps = 1e-6`, авторский `snap_eps = 0.10`.
- Схема — `engine/schema/engine-scene.schema.json`. Её пишут в фазе 1 по таблице полей ниже; после этого она источник правды.

## Зачем

Сейчас каждую локацию модель пишет руками как three.js-страницу на 1000–1500 строк: стены, двери, коллизию, расстановку, проверку. Каждый раз заново, каждый раз те же ошибки. Движок забирает всё механическое себе. Модель (Claude, Muse) пишет только **описание места** в JSON, движок собирает из него мир, ассеты и проверку.

Правила из `AGENTS.md` остаются: код строит пространство, Muse Image рисует поверхности, SAM3D делает предметы, всё параллельно, проверка листом «референс | результат».

## Что ломалось при ручной сборке

| Ошибка | Чем закрывает движок |
|---|---|
| стены видны только снаружи (перепутан обход) | обход нормализуется, сторону стены автор не задаёт |
| две комнаты рисуют одну стену дважды, дверь режет одну | стены строятся из плана уровня, совпадающие рёбра сливаются |
| соседние комнаты разошлись на 0.3 м, между ними полость | линтер называет оба ребра и число, на сколько сдвинуть |
| мебель перекрывает дверной проём | линтер: коридор проёма и сектор полотна свободны |
| предмет в стене / висит / утонул / не на своём месте | линтер по габариту (`size` до сборки, факт после) |
| GLB чёрный (SAM3D пишет metalness=1) | нормализация ассета |
| неизвестный масштаб и перед GLB | равномерный масштаб по `size`, `front_deg` в кэше |
| знак yaw, перепутанные оси | `face` вместо `yaw`, одна таблица углов, `top.png` с подписями |
| скриншот раньше, чем догрузились текстуры | `__ready` только после всех ассетов |
| коллизия расходилась с геометрией | один полилайн для меша и коллизии |
| круглая комната, кривые наклейки (H16) | ребро-дуга, позиция `az` |

## Соглашения

- Метры, мировые координаты везде.
- Оси three.js: X вправо, Y вверх, Z на зрителя. План — плоскость XZ; на `top.png` X вправо, Z вниз.
- **`at` всегда точка `[x, z]` на плане.** 3D-точка (свет, камера) — поле `pos: [x, y, z]`.
- **Позиция на ребре** — поле `on: {"room": id, "edge": i, "t": 0..1 | "m": метры | "az": градусы}`. `t` и `m` — центр вещи, по длине ребра (у дуги — по длине дуги) **от `shape[i]` автора**, при любом обходе. `az` — только для дуги: угол из центра окружности по таблице углов. Если у вещи есть и `room`, и `on.room`, они обязаны совпадать.
- **Все углы** (`yaw`, `dir`, `az`) в градусах, одно правило = `rotation.y` three.js:

| угол | перед / направление |
|---|---|
| 0 | +Z |
| 90 | +X |
| 180 | −Z |
| 270 | −X |

  Перевод из H16 (там `az` 0 = −Z, по часовой): `az_spec = 180 − az_h16`.

  Поворот локального смещения `(lx, lz)` на угол θ: `(lx·cosθ + lz·sinθ, −lx·sinθ + lz·cosθ)`.
- Перед предмета = его +Z до поворота. `size` предмета — `{"w","d","h"}` в его системе до поворота. `size` наклейки — `{"w","h"}`, её `y` — центр.
- `level` у вещей не пишется: он выводится из `room`. Исключение — вещи вне комнат (`walls`).
- **`on` (объект) — всегда позиция на ребре.** «Стоит на другом предмете» — `mount: {"top_of": id}`.
- **`y` у предмета с `mount: wall` — его низ; `y` у наклейки — её центр.**
- SCENE.json — строгий JSON: без комментариев и висящих запятых (примеры ниже — jsonc только для пояснений).
- Id комнат, проёмов, предметов и лестниц — `^[A-Za-z][A-Za-z0-9_-]*$`, иначе `SCHEMA_TYPE` (`{path}: id "{v}" — только латиница, цифры, _ и -`). Символы `#`, `:`, `.` зарезервированы за адресами (`room#i`, `walls#i`) и сгенерированными id (`chairs.0`, `living#1:in:0`, `cap:0`).

- Свободная стена `walls[i]` — интервалы плана без своей комнаты, адрес в сообщениях `walls#<i>`, лица с обеих сторон из `walls[i].material`; `glass: true` → материал `transparent`, но для капсулы и предметов стена твёрдая.
- `fixtures[i]` — бокс: задняя грань по `from → to`, перед — по нормали внутрь `room`; меш тела `fixture.<i>`, верх — плоскость `fixture.<i>:top` (материал `top`, без него — `material`). Для линтера предметов и навигации — твёрдое тело с именем `fixture.<i>`.

### Модель стены

- `shape` — **ось** стены. Ребро `i` идёт от `shape[i]` к `shape[(i+1)%n]`. Компилятор приводит обход к одному направлению и сохраняет нумерацию автора.
- Слияние плана уровня (рёбра комнат + `walls`):
  1. Вершины уровня ближе `snap_eps = 0.10` м сливаются в одну; сдвиги пишутся в паспорт.
  2. Прямые рёбра группируются как коллинеарные при угле между **прямыми** < 2° (направление не важно: антипараллельные рёбра соседних комнат сливаются) и расстоянии < `snap_eps`. Группа режется по проекциям всех концов на одномерные интервалы; у каждого интервала свой набор сторон-комнат (0, 1 или 2). Так решаются частичное перекрытие и Т-стыки.
  3. Дуги сливаются только при совпадении центра и радиуса в пределах `snap_eps`.
  4. Тело стены: интервалы плана сшиваются в цепочки по общим вершинам (цепочка рвётся в вершине степени ≠ 2); каждая цепочка offset'ится clipper2 на `thickness/2` с `JoinType.Miter` (limit 2), `EndType.Joined` для замкнутых цепочек (кольцо по обе стороны оси; `Polygon` дал бы сплошной блок), `EndType.Square` для открытых (конец заходит на t/2 и перекрывается соседней стеной в Т- и Г-стыке, выемки на углу нет); свободный конец `walls[]` — `Butt`; затем union. Проёмы вычитаются из готового тела. Толщина интервала = максимум толщин его сторон. Балки — тоже твёрдое тело для предметов и навигации.
  5. Высота тела — максимум высот соседних комнат; каждая сторона обрезается по своему потолку. Сторона без комнаты получает `style.exterior`.
- Дуга: вершина `[x, z, {"bulge": b}]` делает ребро от неё дугой; `b` = стрелка / половина хорды (модуль как в DXF, `0 < |b| ≤ 1`), пишется на **начальной** вершине дуги. Знак — **не как в DXF**: `b > 0` — выгиб наружу от комнаты, `b < 0` — внутрь; «внутри» определяется полигоном по хордам, знак не зависит от обхода. Разбиение ≤ 0.25 м, **один полилайн для меша и коллизии**.
- `circle` = одно ребро-дуга с индексом 0; `t = 0` в точке az = 0 (+Z от центра), `t` растёт по возрастанию az. Ребро замкнутое: `m` берётся по модулю длины, вещь может пересекать `t = 0`.
- Проём на дуге: сегменты полилайна между концами хорды проёма убираются, вместо них плоский откос по хорде. `center` проёма — точка оси (на дуге) при его `m`; откос и коридор — по хорде.
- **Плоские и настенные вещи** (наклейки, полотна-декали, `mount: wall`) ставятся на **внутреннюю грань** стены (ось ∓ `thickness/2`) + 0.02 м. На дуге — хорда внутренней грани (радиус R ∓ t/2), концы хорды на грани + 0.02 (у выпуклой внутрь грани, `b < 0`, — середина хорды на грани + 0.02); нормаль — радиальная в точке `m`. Ширина на дуге — по хорде: диапазон по `m` = `m ± R·asin(w/2 / R_f)`, `R_f` — радиус грани (у проёма — R оси).
- **Перекрытие между уровнями** = след верхней комнаты × `[y_верх − slab, y_верх]`, `slab = next.y − y − height` нижней комнаты; торцы перекрытия — `exterior`.

### Проёмы

- Задаются `at` (точка на плане; компилятор ищет ближайшую стену в пределах `snap_eps`) или `on` (явное ребро). Не нашёл стену — ошибка с расстоянием до ближайшей и её адресом.
- Компилятор прорезает обе стороны и пишет в паспорт ребро, смещение `m` в метрах и соединённые комнаты. Ребро и `m` — по первой в `rooms` комнате, у которой есть это ребро. `sill + height` выше потолка любой из двух комнат — `OPENING_TOO_HIGH`. Проём должен целиком лежать на одном интервале стены (`OPENING_OFF_EDGE`) и не пересекать другой проём (`OPENING_OVERLAP`). В паспорте окна `rooms` = `["living"]` (одна комната).
- За проёмом нет комнаты → обязателен `outside`.
- Полотно, петля и сектор есть только у `door` с `leaf`; сектор — только при `leaf.open: true`. У `door` без `leaf` и у прочих проёмов в паспорте `swing`/`hinge`/`hinge_at` = `null`.
- `leaf.open: false` — дверь закрыта: связь комнат в графе есть, прохода капсуле нет (стеклянные двери, двери в никуда-но-с-комнатой).
- Полотно открытой двери открывается в комнату `swing`. По умолчанию это комната, дальняя от `spawn` по графу (квартирная дверь с площадки открывается внутрь квартиры); при равном расстоянии — первая в `rooms`; дверь с одной комнатой открывается в неё.
- Петля `hinge`. Пусть `n` — единичная нормаль внутрь `swing`-комнаты, взгляд `f = −n`, лево `L = (f.z, −f.x)` (при взгляде в −Z лево = −X). Левый косяк = центр + L·width/2 (на дуге центр — середина хорды проёма, косяки — концы хорды: откос идёт по хорде). По умолчанию петля — косяк, ближайший к **ближнему из двух концов авторского ребра `swing`-комнаты** (к углу; от обхода не зависит); ничья (|Δ| < 1e-3, дверь по центру ребра) → левый. Петля стоит на внутренней грани со стороны `swing`.
- Сектор полотна: четверть круга радиусом `width` с центром в петле, в сторону `swing`-комнаты. Входит в линтер.
- **Коридор проёма** = `width` × 0.8 м в обе стороны от оси стены, по высоте `[sill, sill + height]`.

### Предметы

- `at` — центр следа на полу (для `ceiling`/`wall` — проекция).
- `mount`:
  - `floor` — низ на полу;
  - `ceiling` — верх под потолком, а если над следом балка — под балкой;
  - `wall` — задняя грань на ближайшей к `at` стене (или `on`), низ на высоте `y`, перед от стены; `face`/`yaw` не нужен;
  - `{"top_of": id}` — низ на верхе опоры, `at` по умолчанию её центр.
- Ровно одно из `face`/`yaw` обязательно для `floor` и `top_of` (кроме `around`). У `ceiling` без `yaw` — 0. `face: "room"` — от ближайшей стены внутрь; если от `at` до внутренней грани этой стены больше 1.0 м — предупреждение `FACE_ROOM_FAR` (для острова и стола задай `yaw` или точку).
- `around` заменяет `at` и `face`/`yaw`: `n` копий по кругу радиуса `r` вокруг `center`, первая на угле `start` (по умолчанию 0) по таблице углов, остальные через `360/n`, каждая смотрит в центр. Копии получают id `<id>.0 … <id>.n−1`; ошибка про копию: `"path": "/props/<i>", "copy": k`.
- Масштаб равномерный по высоте (`h`).
- Расстояние «до стены» везде — до оси, кроме `face: "room"` / `FACE_ROOM_FAR` (до внутренней грани). У дуги «ближайшая точка» и нормаль — радиальные.
- **Коллизия и пересечения — по OBB**: прямоугольник следа, повёрнутый на итоговый yaw, × `[низ, верх]`. AABB — только справочно в паспорте.

### Лестницы

- `from.at` — середина первой подступеньки, `dir` — куда идти вверх.
- `N = round(Δy / rise)`, фактический подъём `Δy / N`. Подступенков N, проступей N−1, длина марша `(N−1) · going`. Выход = `from.at + dir · (N−1) · going`, он обязан лежать внутри `to.room`.
- Просвет — по вертикали от линии носков ступеней до любого твёрдого над ней: потолок, балка, стена, низ перекрытия.
- Вырез делается **только в перекрытии под `to.room`** — там, где просвет < 2.0 м. Где над маршем не `to.room` и просвета не хватает — ошибка `STAIR_HEADROOM` с интервалом по оси марша и минимальным просветом.
- `rail: true` — перила по сторонам марша, где до стены > 0.15 м, и по краю выреза.
- Геометрия: ступени — сплошные боксы `<stair>:step:<k>`, `k = 1 … N−1`, ступень `k` по оси марша `s ∈ [(k−1)·going, k·going]`, по высоте `[y0, y0 + k·Δy/N]`. Линия носков `y(s) = y0 + r + s·r/going`, `r = Δy/N`. Перила `<stair>:rail:left|right` (по взгляду вверх) — бокс 0.04 × 0.04 по линии носков + 0.9 м. Перекрытие — меш `<верхняя комната>:slab`; вырез получает и оно, и потолок нижней комнаты под ним.
- Лестница даёт в граф ребро `from.room ↔ to.room`; комнаты других уровней входят в `ROOM_UNREACHABLE` и `nav`, если до них есть лестница. Этап `stairs` без лестниц в сцене — `skipped`. Паспорт: `stairs: [{"id", "n", "rise", "len", "exit": [x, z], "cut": [[x,z], ...] | null}]` после `decals`.
- `room.height` — потолок комнаты; `level.y` — отметка пола; перекрытие = `next.y − y − height` ≥ 0 (в v0).

### Навигация

- Слои по уровням плюс полигоны-рампы лестниц с функцией высоты. Сетка 4 см.
- Клетка проходима, если в ней есть пол и в интервале `[пол + step_max, пол + 1.8]` нет твёрдого: стена, балка, низ лестницы, перекрытие, предмет с его реальным вертикальным габаритом (настенный ТВ на 1.0 м мешает, шкаф над столешницей на 1.5 м — тоже, ковёр — нет). `step_max = 0.25`.
- Препятствия: стены, балки, твёрдые предметы (`solid: true`), закрытые двери (`leaf.open: false`). Нетвёрдые предметы не мешают. Стена прорезана для навигации только у открытого проёма с `sill ≤ step_max` и `sill + height ≥ 1.8`.
- Капсула r = 0.25. **Биты хранятся уже после эрозии на r**: клетка = 1, если в ней может стоять центр капсулы (дверь 0.9 → проход 0.4 м).
- Сетка уровня: AABB полов уровня, расширенный на 0.04 и привязанный к кратным 0.04; `origin` — угол клетки `[0,0]` с минимальными x, z; клетка `(i, j)` — квадрат `[x0 + 0.04i, +0.04) × [z0 + 0.04j, +0.04)`. Порядок: строка — фиксированный `j`, внутри строки `i` растёт (X быстрее), строки по возрастанию Z; биты в байте LSB-first.
- Рантайм `floorAt(x, z, y_prev)` возвращает ближайший пол в `[y_prev − 0.5, y_prev + step_max]` или `null`.
- Этап `nav` в `check` даёт `NAV_SPAWN_BLOCKED` (клетка `spawn` непроходима) и `NAV_ROOM_CUT` (комната связна по графу, но капсула в неё не проходит; предупреждение до фазы маршрутов; при `NAV_SPAWN_BLOCKED` не считается). Клетка точки: `floor((x − x0)/0.04 + 1e-9)`.
- `nav.json`:
```jsonc
{"cell": 0.04, "capsule": {"r": 0.25, "h": 1.8, "step_max": 0.25},
 "layers": [{"level": "L0", "y": 0, "origin": [x0, z0], "w": 412, "h": 300, "bits": "<base64, 1 бит на клетку, строки по X>"}],
 "ramps":  [{"stair": "s1", "poly": [[x,z],...], "y0": 0, "y1": 3.6, "axis": {"from": [x,z], "dir": 180, "len": 5.6}}],
 "links":  [{"from": "L0", "to": "L1", "via": "s1"}]}
```
  Высота на рампе — линейно по проекции на `axis` (ступени визуальные, коллизия — пандус).

### Ассеты

- Шаблон промта задаёт движок, автор пишет только предмет: object → «single object, front view facing the camera, whole object, plain white background, no shadow»; tile → бесшовная орто-текстура; decal → орто на белом фоне, белое вырезается в альфу.
- **Ключ кэша**: object — шаблон + промт; tile/decal — шаблон + промт + `aspect`. `size` не входит: он влияет только на масштаб при нормализации, правка `size` не перегенерирует.
- Нормализация GLB: metalness 0, низ на y=0, центр следа в 0, поворот на `front_deg` (ручной в v0, рендер с 4 сторон в отчёте), равномерный масштаб.

## Компилятор

`dreamer build SCENE.json --out dist/`

1. Валидация схемы (`engine-scene.schema.json`, включая диапазоны → `SCHEMA_TYPE`) и ссылок.
2. Ассеты пакетом (Muse Image одним залпом, SAM3D по объекту на GPU), нормализация.
3. План уровня: слияние, проёмы, дуги.
4. Геометрия: полы, потолки, стены с поясами и UV в метрах, балки, `walls`, `fixtures`, двери, лестницы, перила.
5. Навигация → `nav.json`.
6. Вывод `index.html` (three.js). Флаги: `?walk=1`, `?cam=<id>`, `?top=1`, `window.__ready`.

## Проверка

`dreamer check SCENE.json [--built dist/]` → JSON-отчёт.

**Этапы.** `schema` → `plan` (слияние, перекрытие комнат, параллельные рёбра) → `openings` (+ граф) → `stairs` → `props` (+ `fixtures`) → `decals` → `cameras` → `nav`. `routes` — только с `--built`. Есть ошибки на этапе — дальше не идём (одна ошибка плана не даёт 30 каскадных); предупреждения не останавливают. Внутри этапа производные коды не считаются поверх исходных: проём с ошибкой не входит в граф, а `ROOM_UNREACHABLE` проверяется, только если других ошибок у `openings` нет. До `build` предметы проверяются по `size`, после — по факту, и `check` предлагает исправленный `size`.

Каталог кодов закрытый (`engine/src/report/codes.ts`, у каждого этап и уровень); один дефект — одна запись. Схема: `SCHEMA_PARSE` (невалидный JSON: строка и столбец), `SCHEMA_UNKNOWN_FIELD`, `SCHEMA_FUTURE_FIELD` (поле v0.2/v1), `SCHEMA_TYPE` (тип, диапазон: длины ≥ 0, `height`/`width` > 0, `t` ∈ [0,1], `|bulge|` ≤ 1), `SCHEMA_REQUIRED`, `SCHEMA_EXCLUSIVE` (`shape`+`circle`, `at`+`on`, `face`+`yaw`, `tile`+`color`, `t`/`m`/`az`, `around`+`at`/`face`/`yaw`); ключевые слова ajv отображаются на эти коды. Дальше: `ID_DUPLICATE`, `REF_UNKNOWN` (в т.ч. `on.edge` вне `0…n−1`, цикл `top_of`), `REF_KIND` (ассет не того `kind`: `props.asset` → object; `decals.asset`, `leaf.decal`, `outside.backdrop` → decal; `materials.tile` → tile), `POS_INVALID` (`az` на прямом ребре или вне дуги; цель `face` совпадает с `at`), `ROOM_REF_MISMATCH`, `ROOM_SELF_INTERSECT`, `ROOMS_OVERLAP`, `EDGES_DRIFT` (warn), `OPENING_NO_WALL`, `OPENING_OFF_EDGE`, `OPENING_OVERLAP`, `OPENING_TOO_HIGH`, `OPENING_NO_OUTSIDE`, `ROOM_UNREACHABLE`, `STAIR_EXIT_OUTSIDE`, `STAIR_HEADROOM`, `PROP_HITS_WALL`, `PROP_HITS_PROP`, `PROP_IN_DOORWAY`, `PROP_IN_SWING`, `PROP_OUTSIDE_ROOM`, `PROP_NO_FACING`, `PROP_ON_TOO_SMALL`, `PROP_CEILING_LOW`, `PROP_ABOVE_CEILING` (верх выше потолка или низа балки над следом), `PROP_WALL_NOT_FOUND`, `PROP_SIZE_ODD` (warn), `FACE_ROOM_FAR` (warn), `DECAL_OFF_WALL`, `DECAL_ON_OPENING`, `DECAL_OVERLAP`, `DECAL_HIDDEN` (warn), `CAMERA_OUTSIDE` (вне комнат или внутри твёрдого предмета, стены, балки), `NAV_SPAWN_BLOCKED`, `NAV_ROOM_CUT` (warn), `ROUTE_BLOCKED`.

**Отчёт.** `check` печатает отчёт в stdout и пишет его в `--report <path>` (по умолчанию `<dir(scene)>/<name>.check.json`). Код выхода: 0 — ошибок нет, 1 — есть ошибки (в т.ч. `SCHEMA_PARSE`), 2 — внутреннее падение или ввод-вывод. Числа округлены до 1e-3. Порядок — как в SCENE.json, рёбра по (комната, i).
```jsonc
{"ok": true,
 "stages": [{"stage": "schema", "status": "pass" | "fail" | "skipped"}, ...],
 "passport": {
   "edges":    [{"id": "living#3", "from": [4,4], "to": [-4,4], "len": 8.0, "arc": null | {"c": [x,z], "r": 5.8},
                 "normal_in": [0,-1], "sides": [{"room": "hall", "m": [2,6]}], "openings": ["front"]}],
   "snaps":    [{"from": [x,z], "to": [x,z]}],
   "openings": [{"id": "front", "edge": "living#3", "m": 4.0, "rooms": ["living", "hall"],
                 "swing": "living", "hinge": "left", "hinge_at": [0.45, 3.94]}],
   "props":    [{"id": "chairs.0", "yaw": 180, "obb": [[x,z],[x,z],[x,z],[x,z]], "y": [0, 1.3],
                 "aabb": [[x0,z0],[x1,z1]], "wall": null | "living#0", "size": {"w","d","h"}}],
   "decals":   [{"i": 0, "edge": "living#2", "center": [x,y,z], "normal": [x,z]}]},
 "errors": [Issue], "warnings": [Issue]}
```
`sides` — **другие** комнаты на интервалах этого ребра (своя не пишется), `m` — интервал в метрах в координатах **этого** ребра от его `shape[i]`; соседние интервалы с одной комнатой сливаются. `obb` — 4 угла против часовой, начиная с локального (−w/2, −d/2).

**Ошибка (Issue):**
```json
{"code": "PROP_HITS_WALL", "stage": "props", "path": "/props/2/at",
 "msg": "sofa заходит в стену living#0 на 0.18 м", "fix": {"at": [-3.48, 1.5]}}
```
`fix` — частичный объект с готовыми значениями; применяется к ближайшему по `path` узлу, у которого есть все ключи `fix` (`/props/2/at` + `{at}` → в `/props/2`; `/rooms/1/shape` + `{"2", "3"}` → замена элементов самого массива). У копий `around` `fix` нет.

**Сообщения.** Автор-LLM чинит сцену по `msg`, поэтому каждое `msg` содержит id, адрес (`room#i`) и числа «есть → нужно». Шаблоны (`engine/src/report/messages.ts`):

| код | msg | fix (фаза 1) |
|---|---|---|
| `SCHEMA_PARSE` | `JSON не разобран: строка {L}, столбец {C}: {причина}. Комментарии и висящие запятые запрещены` | — |
| `SCHEMA_UNKNOWN_FIELD` | `{path}: неизвестное поле {k}; возможно {ближайшее}` (Левенштейн ≤ 2) | — |
| `SCHEMA_FUTURE_FIELD` | `{path}: поле появится {когда}; сейчас {замена}` (`walls`, `fixtures` → «в фазе 2», «опиши как props»; `stairs` → «в фазе 5», «убери, второй уровень — отдельной сценой»; прочие → «в v0.2» / «в v1», «убери поле») | — |
| `REF_UNKNOWN` | `{path}: {вид} "{v}" не найден; есть: {id, ≤ 10}` | — |
| `ROOMS_OVERLAP` | `{a} и {b} пересекаются на {S} м²` | — |
| `EDGES_DRIFT` | `{a#i} и {b#j} разошлись на {d} м` | вершины ребра |
| `OPENING_NO_WALL` | `{id}: ближайшая стена {room#i} в {d} м (нужно < 0.10)` | `{at}` — проекция |
| `OPENING_OFF_EDGE` | `{id}: [{m0}, {m1}] вне интервала {room#i} [{a}, {b}]` | — |
| `OPENING_TOO_HIGH` | `{id}: sill + height {v} > потолок {room} {h}` | `{height}` |
| `PROP_HITS_WALL` | `{id} заходит в стену {room#i} на {d} м` (глубина — заход OBB за внутреннюю грань по нормали) | `{at}` |
| `PROP_HITS_PROP` | `{id} входит в {other} на {d} м` (path — у более позднего) | — |
| `PROP_IN_DOORWAY` / `PROP_IN_SWING` | `{id} в коридоре / секторе {opening}` | — |
| `PROP_OUTSIDE_ROOM` | `{id}: центр ({x}, {z}) вне {room}` + `; он в {other}` или `; он вне всех комнат` | `{room}`, если в другой |
| `PROP_NO_FACING` | `{id}: нужен face или yaw` | `{"face": "room"}` |
| `PROP_CEILING_LOW` | `{id}: низ {y0} м < 2.0` | — |
| `PROP_ABOVE_CEILING` | `{id}: верх {y1} м выше потолка {room} {h} м на {d} м` | — |
| `DECAL_OFF_WALL` | `decal.{i} на {room#i}: y [{y0}, {y1}] вне [0, {h}]` или `decal.{i}: m [{m0}, {m1}] вне интервала {room#i} [{a}, {b}]` | `{y}` в пределах |
| `NAV_SPAWN_BLOCKED` | `spawn в {id предмета \| стене room#i \| вне комнат}` | — |

Остальные коды — по тому же правилу: id, адрес, числа. С фазы 4 отчёт печатает разницу с прошлым отчётом по тому же пути (что исправилось, что появилось): если файл `--report` уже есть, отчёт получает `diff: {fixed: Issue[], new: Issue[]}` (ключ — `code` + `path`), а stdout после отчёта — строки `исправлено: {code} {path}` / `появилось: {code} {path}`. Первого отчёта без прошлого поле `diff` не имеет.

`STAIR_EXIT_OUTSIDE`: `{id}: выход ({x}, {z}) вне {room}`. `STAIR_HEADROOM`: `{id}: просвет {min} м < 2.0 на оси s [{s0}, {s1}]`. `ROUTE_BLOCKED`: `{route}: застрял в ({x}, {z}) по пути к {цель}; мешает {что}`, `path` = `/routes/<i>/path/<j>` недостигнутой цели.

**Паспорт** идёт в отчёте сразу после `stages`:
- ребро (из demo): `living#3 (4,4)→(-4,4) len 8.0, нормаль внутрь −Z, соседи: hall на m [2,6], проёмы: front`;
- проём: ребро, смещение в метрах, соединённые комнаты, сторона полотна и петля;
- предмет: мировой AABB, итоговый yaw, к какой стене прилип, фактический `size`;
- лестница (фаза 5): число ступеней, длина, вырез.

`top.svg` и `nav.json` (фаза 1, детерминированные) пишутся рядом с отчётом: `<dir(report)>/<name>.top.svg`, `<name>.nav.json`, где `<name>` = имя файла сцены без `.scene.json`. `top.svg` и позже `top.png` подписывают id комнат, номера рёбер, id предметов и проёмов. `top.png` пишет только `build` (`dist/top.png`, снимок `top.svg` в Chromium): `check` браузер не поднимает.

**Линтер — ошибки:**
- неизвестное поле, ссылка, материал, ассет; поля v0.2/v1 в v0;
- комнаты уровня пересекаются по площади > 0.01 м²;
- проём не нашёл стену; выше потолка; за проёмом пусто без `outside`;
- граф: каждая комната достижима из `spawn`;
- лестница: выход внутри `to.room`, просвет ≥ 2.0 м;
- твёрдый предмет в коридоре проёма или секторе полотна; пересекает стену, балку или другой твёрдый предмет; вне своей комнаты;
- дубли id; `room` ≠ `on.room`; самопересечение контура комнаты;
- `on`: помещается на опоре; `ceiling`: низ ≥ 2.0 м; `wall`: ребро своей комнаты ближе 1.0 м от `at`;
- нет `face`/`yaw` там, где обязательны;
- наклейка: внутри `[0, room.height]`, на стене, не на проёме, не пересекает другую;
- камера внутри комнаты по плану и по высоте `[level.y, level.y + height]`, не в теле стены, балке или твёрдом предмете (OBB × его y).

**Линтер — предупреждения:**
- параллельные рёбра разных комнат на расстоянии от `snap_eps` до 0.5 м: «living#1 и bed#3 разошлись на 0.30 м, сдвинь x=4.3 → 4.0»;
- размер вне правдоподобного для `cat`;
- `face: "room"` дальше 1.0 м от стены;
- наклейка закрыта предметом ближе 0.15 м к стене;
- факт и `size` расходятся > 20%.

**Маршруты:** капсула идёт по `nav`; отчёт — точка застревания и что мешает. Только с `--built <dist>`: этап `routes` последним в `stages`, по `<dist>/nav.json` (нет файла → exit 2). Поиск — A* по 8 соседям на битах; между слоями — только по рампе из `links`. Точки пути: `spawn` → `spawn.at`; проём → его центр на полу; предмет → ближайшая проходимая клетка не дальше 0.6 м от его OBB; лестница → `from.at`, затем выход; `{room, at}` → `at`; точка в непроходимой клетке — ближайшая проходимая в радиусе 0.3 м. Точка застревания — достижимая клетка, ближайшая к цели; «что мешает» — ближайшее к ней твёрдое: `room#i`, `walls#i`, id предмета, `fixture.<i>` или `закрытая дверь {id}`. После `build` предметы с GLB проверяются по факту: `PROP_SIZE_ODD` при расхождении > 20% по любой оси, `fix: {"size": факт}`.

**Лист:** скриншоты всех `cameras` рядом с `ref` → `sheet.png`, плюс `top.png`. Ассеты: нет чёрных/пустых текстур, все GLB загрузились.
