## Замечания к спеке v3.1

1. **блокер, §4.** Цитата: *«записки из него всё же применяются»* при `consult_stale`. Ломается: ответ опоздал на `abort_build`/`transition`, мост выкинули, а `messages`/`facts_update` из старой сцены применяются к новой. Актёр в новой сцене получает мотив про старый мост, память засоряется чужими фактами. Фикс: при `stale` отбрасывать всё, кроме `wake_up`; записки разрешать только если `bridge` совпадает или `epoch` тот же; тест: stale-консультация не меняет `messages`/факты.

2. **блокер, §4.** Цитата: *«`abort_build` в `building` → `idle`... сразу следующая консультация»* + *«5:00 → требование»*. Ломается: таймер 2:00/5:00 считается *«от начала сцены»*, после `abort` сцена та же, 5:00 уже прошло — директор сразу получает `forced` в цикле abort→forced→abort. `fail_streak` при этом обнуляется любым `abort_build`, накрутки бесконечны. Фикс: на `abort_build` ставить `scene_clock=0` или отдельный `idle_since`; `forced` после аборта только через N реплик; лимит `abort` подряд → `wake_up("abort_loop")`.

3. **блокер, §5.** Цитата: *«Пауза между репликами = длина аудио Fish... Если голос не пришёл — слова / 2.5 + 1 с»*. Ломается: нет таймаута Fish. Если `voice.py` висит, `sim.py` стоит вечно — противоречит R8/R10 «сон идёт». `Fish 429 → ретрай` без предела усугубляет. Фикс: таймаут TTS e.g. 15 с → fallback на формулу + `stall` в лог + пропуск аудио; ретрай 429最多 3 с backoff, дальше fallback.

4. **блокер, §8 + §4.** Цитата: *«в `building` поля `bridge/destination` игнорируются»* + *«мост и цель заперты»*. Ломается: про `next_scene.objects/actors`, `hero_next`, `messages` в `building` ничего нет. Директор может тихо подменить цель/каст без `abort_build`, проверка это пропустит. Фикс: в `building` игнорировать весь блок цели (`bridge/destination/next_scene/hero_next`), разрешены только `messages/facts_update/abort_build/wake_up`; нарушение → `invalid` + явное правило в промпте.

5. **блокер, §4 + §5.** Цитата: *«TOUCH в `building` → состояние не меняется, лестница замирает»* + *«Лестница по часам сборки: L0 0:00...»*. Ломается: лестница «замерла», а `build%` растёт и требует *«новая отговорка на каждую стадию»*. Актёр получает замороженный `hint_level` + растущий `build%` — вести к мосту нельзя, но надо тянуть к нему же. Непонятно, что значит «замирает». Фикс: зафиксировать: при раннем TOUCH `hint_level` не растёт до `ready`, актёр получает флаг `stalled=true` и отвечает только отговоркой по `build%`; тест на отсутствие `[[LOOK]]` в отговорках.

6. **важно, §7.** Цитата: *«слои ≤ 3500, система + схема ≤ 1500, оперативный хвост ≤ 800 — весь промпт ≤ 5800»*. Ломается: 3500+1500+800=5800 без запаса, любое округление `max(символы/4, слова×1.33)` даёт превышение. Хвост сам может превысить 800 (очередь событий при заторе директора). Шаг 1 проверяет *«промпт ≤ 6000»* — не 5800. Фикс: бюджет e.g. 3200+1400+700=5300 лимит 5800; резать хвост первым (сводка очереди), потом эпизоды; унифицировать проверку на 5800 везде.

7. **важно, §7.** Цитата: *«слияние всегда из них [episodes_raw/], не из сводки сводок»* + R10 *«Сон идёт, пока пользователь не остановит»*. Ломается: raw-копии и `log.jsonl`/`consults/`/`audio/` растут бесконечно, защиты `--max-dollars/--max-minutes` диск не ограничивают. Долгий сон уронит диск/SSE-повтор. Фикс: добавить `--max-gb` или ротацию: raw старше N сцен сжимать/удалять после слияния, в лог `budget_trim_disk`; шаг 3 проверяет размер.

8. **важно, §5a.** Цитата: *«код вырезает все [...] и [[...]]... а сам текст оборачивает в `[HUMAN_SAYS: ...]`»* + *«строка сказать за героя... NPC-ход отменяется»*. Ломается: неясно, проходит ли `POST /say` ту же санитизацию, и что происходит с вырезанным `[[TOUCH:clarinet]]` — клик по предмету тоже идёт через `resolve_touch()`. Инжект через `/say` может форсировать TOUCH/LOOK. Тест заявлен только для ввода. Фикс: один `sanitize()` для `/say`+/event`/click; вырезанные теги → `input_rejected` в лог, TOUCH только через `resolve_touch()` по `objects[]`.

9. **важно, §6 + `gate_test.py`.** Цитата: *«Ключ — `fish_key()` как в gate_test»*. Ломается: `fish_key()` читает абсолютный `/Users/terobyte/.../.env`. 10. **важно, §15 шаг 6.** Цитата: *«второй директор получает тот же транскрипт, но с чужой душой»*. Ломается: транскрипт уже содержит поведение актёров, ведомых настоящей душой (записки/намёки), контроль заражён. `forced`-решения при требовании после 5:00 будут одинаковыми, судья сравнит не душу, а стиль `why`.
