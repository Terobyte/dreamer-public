## Стек: Meta Model API ✅

- **Base URL:** `https://api.meta.ai/v1`, ключ `MODEL_API_KEY`.
- **Совместимость:** drop-in с OpenAI SDK (Chat Completions + Responses) и Anthropic SDK (Messages). Заявлена работа с Claude Code и OpenCode.
- **Подводные камни:**
  - Muse Spark рассуждает всегда: `reasoning_effort: "none"` → HTTP 400.
  - Chat Completions не переносит reasoning между ходами. Для агентных циклов используй **Responses API**.
- **Список моделей:** `GET /v1/models`.

### NPC: актёр и мозг (развитие Synapse)

Сейчас эскалация в Synapse явная: «передал в мозг». В Dreamer **связь скрыта**:

- **Актёр** — Spark 1.3, низкий reasoning effort, нужна скорость. Голосовой цикл берём из Synapse (pipecat):
  - Deepgram → **Muse Voice Transcribe** (realtime WS);
  - Gemini → **Spark**;
  - TTS остаётся Fish (у Meta TTS нет).
- **Мозг = режиссёр** (решение Oct 26). Отдельного мозга на каждого NPC нет: `consult()` уходит одному режиссёру (Wonder), ответ возвращается как `npc_note`. Один источник правды о сюжете. Работает асинхронно, в разговоре не участвует.
- **Как прячем связь:**
  1. У актёра есть неблокирующий инструмент `consult(...)`. Пока мозг думает, актёр тянет время **в образе** — у каждого NPC свой тик: «хм…», затягивается трубкой, отвечает вопросом.
  2. Ответ мозга приходит скрытым сообщением-«мыслью» персонажа. Актёр вплетает его в следующую реплику как свою.
  3. Мозг сам присылает «режиссёрские заметки» по сюжетным битам: актёр ведёт игру, но сюжет у мозга.
  4. Выходной guard (по образцу `synapse/guards.py`) вырезает мета-фразы до TTS: «передам», «уточню у», «модель», «AI».

**Риски для проверки в первый день:**
- Spark рассуждает всегда → замерить время до первого токена. Если больше ~1.5 с, у актёра должна быть заготовленная первая фраза.
- SAM 3D на Modal → замерить секунды на объект. Отсюда лимит объектов в сцене (цель 5–10).

### Живой режиссёр: сон перестраивается на ходу

**Ключевая мысль:** во сне переходы и так бессвязны. «Логика сна» прячет задержку генерации — то, что в игре было бы багом (локация сменилась без объяснения), во сне ощущается естественно.

**1. Сначала каркас, потом импровизация** (как в HAMLET).
- Wonder пишет каркас сна: вход → 2–4 сцены → кульминация → пробуждение.
- Каждая сцена — storylet (как в Dramamancer): `условия → исходы → переходы`.
- Пробуждение — жёсткая граница: сон всегда заканчивается, демо не зависает.

**2. Режиссёр меняет сцену патчами, а не перегенерацией.**

Wonder выдаёт строгий JSON, который валидируется по схеме и ложится на ECS IWSDK:

```
spawn(asset, pos) · remove(id) · morph(id → asset) · relight(mood)
skybox_swap(pano) · fog(density) · npc_note(npc, note) · transition_to(scene, style)
```

Что вызывает тик режиссёра — **события, а не таймер:**
- игрок сказал или сделал что-то значимое;
- закончился сюжетный бит;
- взгляд задержался на объекте;
- NPC отыграл свою заметку.

Так экономим токены Wonder.

**3. Два темпа перестройки.**

| | Что делает | Когда виден результат |
|---|---|---|
| **Микро** | Переставить, перекрасить, сменить свет / туман, выдать NPC новую заметку, создать объект **из кэша** | Мгновенно |
| **Макро** | Новая локация, новые объекты: Image → SAM 3.1 → SAM 3D | Минуты — фоном, пока игрок в текущей сцене |

**4. Упреждающая генерация.** Пока игрок в сцене N:
- режиссёр уже держит **2 кандидата сцены N+1** (ветки storylet);
- конвейер ассетов генерирует их заранее, пока игрок ещё в сцене N;
- ветку выбирает поведение игрока; невыбранная остаётся в кэше и может пригодиться позже.

**5. Эластичные переходы.** Длительность перехода не фиксирована: она растягивается, пока ассеты не готовы.
- Переходы — это **сюжетные приёмы**, а не экраны загрузки:
  - туман сгущается;
  - дверь ведёт не туда;
  - объект превращается в другой: сплаты рассыпаются и собираются заново ⚠️ (проверить анимацию сплатов в Spark);
  - небо перетекает в новую панораму;
  - NPC говорит: «ты здесь уже был…».
- Если генерация опаздывает, рассказчик (Fish TTS) тянет переход ещё на один бит.

**6. Повторяющиеся мотивы.** Кэш ассетов переиспользуется между сценами. Предмет из дня (кружка, ключи) появляется во всех сценах в разных ролях. Психологически это правдиво (так работают сны) и дёшево (уже сгенерировано).

**7. Осознанный сон — wow-момент для демо.** Игрок говорит вслух «хочу летать» или «пусть пойдёт дождь»:
- Voice Transcribe → режиссёр → патч;
- микро-действие срабатывает мгновенно, макро — через переход.

Это показывает, что режиссёр живой, а не заранее записанный ролик.

### Инструменты режиссёра (полный набор)

Режиссёр (Wonder) дёргает инструменты через function calling как хочет. Клиент (IWSDK ECS) исполняет **мгновенные** операции сразу, **асинхронные** возвращают тикет.

**Видеть** (read-only):

| Инструмент | Что возвращает |
|---|---|
| `scene_state()` | Объекты, NPC, свет, туман, небо |
| `player_state()` | Позиция, **на что смотрит**, последние слова, скорость |
| `npc_transcripts(npc?)` | Диалоги |
| `asset_queue()` | Что генерируется и когда будет готово |
| `cache_search(query)` | Уже готовые ассеты и мотивы |
| `day_log(query)` | Факты из дня игрока |

**Мир** (мгновенно):
- **Объекты:**
  - `spawn(asset, place)`, где `place` семантический: «на столе», «далеко слева», «над головой», **«за спиной»**;
  - `remove`, `move`, `scale`;
  - `morph(id → asset)` — сплат рассыпается и собирается в другой;
  - `animate(id, float | orbit | pulse | drift | follow_player)`;
  - `tint(id, color)`;
  - `physics(id, on | off)`.
- **Атмосфера:**
  - `relight(mood, color, intensity)`, `fog(density, color)`, `time_of_day(t)`;
  - `weather(rain | snow | ash | petals | none)`;
  - `skybox_swap(pano, crossfade_s)`.
- **Игрок:**
  - `player_locomotion(walk | float | fly | fall)`;
  - `player_scale(x)` — стать крошечным или великаном;
  - `gravity(g)`.
- **Звук:** `ambience(track)`, `sfx(name, at)`, `music_mood(mood)`.

**Персонажи:**
- `npc_spawn(card, place)`, `npc_despawn`;
- `npc_note(npc, note)` — скрытая заметка, не произносится вслух;
- `npc_goto(npc, place)`, `npc_emote(npc, emotion)`;
- `npc_merge(a → b)` — один человек во сне становится другим;
- `narrate(text)` — голос рассказчика.

**Сюжет и генерация** (асинхронно):
- `generate_asset(prompt, kind = object | panorama | npc_body)` → тикет;
- `prepare_scene(spec)` → тикет на всю локацию (см. ниже);
- `transition_to(scene, style, min_s, max_s)`;
- `set_flag(k, v)`, `beat_complete(id)`;
- `wake_up(reason)`.

**Защита:** «все инструменты» ≠ «без границ».
- Каждый вызов проходит JSON-схему.
- Лимиты: не больше N ассетов на сон, тиков в минуту и $ на сон.
- Промпты генерации проходят контент-фильтр.
- Тот же принцип fail-closed, что в гейте Synapse.

### Сборка новой локации

**1. Спецификация** (Wonder, пока игрок ещё в сцене N). `prepare_scene(spec)`:

```json
{ "id": "lake_in_mug", "mood": "тихая тревога, сумерки",
  "panorama": "равноудалённая 360° панорама: ...",
  "bridge": "mug_01",
  "objects": [{"prompt": "...", "size_m": 0.4, "place": "на берегу", "priority": 1}],
  "npcs": [{"card": "...", "hidden_goal": "..."}],
  "entry_beat": "..." }
```

**`bridge`** — объект-мост, который есть в обеих сценах. Он держит непрерывность: «кружка в руке» → «озеро внутри кружки».

**2. Параллельная генерация** на Modal, по приоритету:
1. **Панорама**: Muse Image, 360° (формат 2:1 — ⚠️ проверить, поддерживается ли; фолбэк — широкий кадр + `images/edits` для outpainting) → небо.
2. **Объекты-герои** (priority 1): Muse Image (объект на чистом фоне) → SAM 3.1 (маска по тексту «the lamp») → SAM 3D Objects → splat `.ply` → сжатие → кэш.
3. **Остальное** (priority 2+) — тем же конвейером, после героев.

**3. Раскладка.**
- Семантическое `place` → солвер колец вокруг игрока: 1.5 м / 4 м / 10 м + высота.
- Масштаб берётся из `size_m`: SAM 3D отдаёт нормализованный объект.
- Без физического солвера — для сна хватает «примерно правильно».

**4. Уровни готовности:**

| Уровень | Что готово | Что можно делать |
|---|---|---|
| **L0** | Панорама + мост | Переход можно **завершить** |
| **L1** | Объекты-герои | Входной бит сцены |
| **L2** | Остальное | Догружается **после** входа: проявляется из тумана, где игрок не смотрит |

### Хореография перехода

| Шаг | Что происходит |
|---|---|
| **t0 — Зерно** | `narrate("ты слышишь стук… изнутри кружки")` + `npc_note` «намекни на кружку». Сюжет начинает вести к переходу **до** того, как он начался |
| **t1 — Сигнал** | Мост оживает: `animate(mug, pulse)`, свет тянется к нему, NPC смотрит туда |
| **t2 — Растворение** | `fog` ↑, сплаты сцены N рассыпаются в частицы, звук уходит под воду. Мост остаётся чётким |
| **t3 — Лиминальная пауза (эластичная)** | Туман + мост + рассказчик. Держится, пока нет **L0**, максимум `max_s` (~45 с). Если генерация не успела — подставляем кэшированный вариант сцены, игрок разницы не знает |
| **t4 — Сборка** | `skybox_swap` crossfade, частицы собираются в объекты L1, туман редеет |
| **t5 — Вход** | `entry_beat`: NPC начинает разговор, L2 проявляется по краям |

**Каталог стилей перехода** (выбирает режиссёр):
- **`door`** — дверь ведёт не туда.
- **`fall`** — пол исчезает, падение сквозь облака.
- **`into_object`** — уменьшаемся и входим внутрь моста (кружка → озеро).
- **`false_awakening`** — «проснулся» в своей комнате, но что-то не так.
- **`look_away`** ⭐ — сцена меняется **за спиной**, пока игрок не смотрит. Повернулся — комната другая.
  - Работает на слепоте к изменениям (change blindness): мозг не замечает перемен вне поля зрения. Подход известен в VR-исследованиях (redirected walking).
  - **Нулевая видимая задержка:** собираем L1 позади игрока, пока он смотрит вперёд.
  - Нужен `player_state().gaze` — IWER эмулирует взгляд.
- **`color_wash`** — мир заливается одним цветом и проявляется заново.
- **`crowd_morph`** — NPC вокруг по одному превращаются в людей новой сцены (`npc_merge`).

### Осознанный сон: два канала

Фраза игрока «хочу летать» идёт по **двум каналам параллельно**:

```
голос → Voice Transcribe ─┬─► БЫСТРЫЙ: Spark классифицирует намерение
                          │     → мгновенный инструмент (player_locomotion=fly)
                          │     → ≲1–2 с, игрок уже летит
                          └─► МЕДЛЕННЫЙ: событие уходит режиссёру (Wonder)
                                → сюжетное последствие: «внизу кто-то машет тебе…»
                                → может запустить prepare_scene
```

- Быстрый канал отвечает за «вау», медленный — за смысл.
- Без быстрого канала будет 5 с тишины и магия умрёт.
- Если намерение невыполнимо или запрещено, быстрый канал отыгрывает в образе: «ты пытаешься взлететь… но ноги будто вросли в песок». Отказ становится частью сна.

**Стоимость:** тик режиссёра — это короткий контекст (состояние сцены + последние события) и короткий JSON на выходе. При тиках по событиям, а не каждые N секунд, бюджет Wonder на один сон — центы.

### Питч и приватность

Не говорить на питче «собираем данные». Говорить: «пользователь сам приносит свой день, и ему это выгодно — сон строится из его жизни». Данные дня принадлежат пользователю.

Посторонние люди в кадре очков — это юридический вопрос (GDPR и т.п.), а не вопрос доверия пользователя. Решение: SAM 3.1 вырезает или размывает чужие лица до того, как кадр попадает в сцену. Сказать это одной фразой.

### Решения (Oct 26)

- **Трек:** Indie. **Команда:** соло.
- **Язык:** английский (NPC, рассказчик, UI, видео).
- **Ввод дня:** фото + голосовая заметка → Spark vision → дневник. Плюс встроенный **demo day**: готовый набор фото и заметки, чтобы судья мог запустить сон без своих данных. Mock Device Kit — только в видео, если останется время.
- **Стек:** Python-бэкенд (форк голосового цикла Synapse на pipecat + режиссёр + очередь генерации) ↔ WebSocket ↔ IWSDK-сцена в браузере. C++ не нужен: узкое место — сетевые вызовы моделей и GPU на Modal, а не CPU. Рендер сплатов уже идёт на GPU в Spark.js.
- **Движок, а не симуляция:** LLM-native инструменты, опыт = карточка сессии. **Мозг = режиссёр.** Предгенерация в ритуале засыпания.
- **Реальные люди → архетипы.** Никого из реального дня не показываем под настоящим именем и с настоящим лицом. Режиссёр делает персонажа, *вдохновлённого* человеком: новое имя, другая внешность, та же роль и эмоция («строгая начальница» → «Смотрительница маяка Орла»). Правило в системном промпте Wonder + guard на выходе: имена из дневника не должны попадать в реплики и TTS. Лица посторонних с фото в генерацию не идут.

### Движок: LLM-native

Движок спроектирован так, чтобы им управляла модель, а не программист. Инструменты — это глаголы, которыми думает LLM.

1. **Семантические аргументы.** `spawn("lamp", "behind the player")`, `relight("quiet dread")` — без координат и матриц. Перевод в числа делает движок (солвер колец, таблица настроений).
2. **Мир читается как текст.** `scene_state()` отдаёт компактный JSON со стабильными id и короткими описаниями: модель видит сцену, не разбирая scene graph.
3. **Ничего не блокирует модель.** Всё медленное — тикет + уровни готовности L0/L1/L2. Модель продолжает играть, пока ассет строится.
4. **Ошибки обучают.** Невалидный вызов возвращает, что не так, и допустимые варианты («place `under the sea` unknown; try: …»). Модель исправляется сама за один ход.
5. **Границы в движке, а не в промпте.** JSON-схема, лимиты ассетов / тиков / $, контент-фильтр, fail-closed.
6. **Опыт = данные.** **Карточка сессии** (JSON): промпт режиссёра, правила, набор ассетов, подмножество инструментов, правила безопасности. Новый опыт — новый файл, не новый код.
7. **Один реестр инструментов, открытый по MCP.** Режиссёром может быть Wonder, Spark или любой другой агент. Тот же MCP я использую для тестов сцены без шлема.
8. **Журнал = повтор.** Каждая сессия — лог вызовов инструментов. Его можно детерминированно проиграть заново: для отладки и для чистой записи видео.
9. **Тики по событиям**, не по таймеру.
10. **Любой ввод = событие-текст.** Голос, взгляд, жест, штрих на доске, нажатая клавиша — всё превращается в короткое событие в журнале (`{"type":"key","instrument":"piano#1","note":"C4"}`, `{"type":"drawing","board":"board#1","png":"…","caption":"…"}`). Модель не видит устройств ввода — только события.
11. **Инструменты-объекты по требованию.** Бог-ИИ вызывает `summon("whiteboard", "in front of the player")`, `summon("piano_keys")`, `summon("keyboard")`, `summon("cards", ["да","нет","не знаю"])`. Каждый инструмент-объект — модуль движка со своей схемой ввода и событий. Набор расширяемый: новый инструмент пишет комьюнити, а не режиссёр.

12. **Контекст = сценарий с пропусками (главный принцип).** Без контекста ИИ ничтожен: он лишь продолжает то, что уже написано. Поэтому 100% действий не пишем, а пишем **опоры**, и модель достраивает между ними. Карточка сессии — это в первую очередь пакет контекста:
    - **канон** — факты мира, которые нельзя выдумывать (меню и цены в McDonald's, кто такой начальник, что было днём);
    - **биты** — цели сцены по порядку («клиент делает заказ → кассир предлагает комбо → ошибка в заказе»);
    - **образцы реплик** — как персонаж отвечает на типичные фразы («Что-нибудь ещё?», «Соус к картошке?»), чтобы задать голос и манеру;
    - **импровизация** — всё, что между опорами, модель пишет сама.

    **Опоры пишет не человек, а сам движок (метасборка).** Пользователь бросает вайб («я Спанч Боб…»), движок сначала вытаскивает из модели библию мира (канон, персонажи, образцы реплик, биты), проверяет её на противоречия, и только потом строит сцену. Модель уже знает мир Спанч Боба, наша задача — достать это знание в структуру до того, как она начнёт импровизировать. Ручная карточка — частный случай.

    Движок не скармливает всё сразу: на каждом тике **собирает срез** — текущий бит, нужный канон, 2–3 близких образца и последние события. Умный контекст — работа движка, не модели.

**Слои (кто что делает):**

| Слой | Что | Кто пишет |
|---|---|---|
| Движок | рендер, солвер мест, реестр инструментов, ввод → события, журнал, лимиты | мы |
| Инструменты-объекты | доска, клавиатура, клавиши, карточки, рисунок… | мы (база) + комьюнити |
| Скиллы | «как вести»: нарратор, психодраматист, учитель, интервьюер — промпт + подмножество инструментов + метрики | мы (2–3) + комьюнити |
| Карточки сессий | конкретный опыт: роль, мир, цель, безопасность | комьюнити / пользователь |
| Бог-ИИ (рантайм) | вживую собирает сцену и зовёт инструменты по ходу | модель |

**A/B скиллов.** Одна карточка, два скилла → прогон на сценарии-фикстуре (записанные события игрока из журнала) → LLM-судья + метрики (латенси, число ошибок вызовов, «держит ли роль»). Журнал делает A/B дешёвым: ввод игрока воспроизводится без человека.

### Питч и Impact

**Одна фраза:** *Dreamer — LLM-native движок опыта: ты приносишь свой день, а модель строит вокруг тебя мир, в котором можно прожить, отрепетировать или выучить что угодно.*

- **Impact = опыт по запросу.** Не развлечение: проживание и репетиция. Психологическая сессия **вдохновлена психодрамой** — реальным методом, где клиент проигрывает ситуацию с актёрами; наши NPC и есть эти актёры.
- ⚠️ **Не говорить «психотерапия»** — это медицинское обещание. Говорить: «пространство для репетиции и проживания».
- **Безопасность:** признаки дистресса в речи → режиссёр делает мягкий `wake_up()` и показывает ресурсы помощи. Правило в карточке сессии + guard.
- **Общность показываем, а не заявляем:** один движок, три карточки сессии.
- Видение Meta («опыт по запросу») — одна фраза в питче, не центр.

**Структура видео:**

| | Сессия | Зачем |
|---|---|---|
| **Главная** (~60%) | Сон из твоего дня: тяжёлый разговор с начальником → архетип «Смотрительница маяка», проговорить заново | Ввод дня + психодрама + живые NPC + осознанный сон |
| Клип 2 | Репетиция: собеседование или выступление перед залом NPC | Чисто голосовая, полностью работает в эмуляторе |
| Клип 3 | Урок: язык или «поговори с Сократом» | «Получать опыт» |

Фортепиано и прочие задачи с точной моторикой рук — не в демо: без шлема не проверить.

**Ритуал засыпания** (честная предгенерация). Пользователь загружает фото и голосовую заметку, и пока он готовится и надевает шлем (3–5 мин), конвейер строит сон. Вживую генерируются только панорама и осознанные желания. Это устройство продукта, а не костыль для демо.

### Гипотезы и замеры — первыми

Ничего не строим поверх непроверенного. У каждой гипотезы есть критерий прохода и заранее выбранный фолбэк.

| # | Гипотеза | Как мерим | Проход | Если нет |
|---|---|---|---|---|
| **H0** | **Вайб → метасборка.** Пользователь говорит сырую безумную идею одной фразой, движок сам собирает мир: библию мира, локацию, персонажей, живой разговор. Никаких заготовок под идею | 3 идеи пользователя. **№1 (известна):** «я Спанч Боб, просыпаюсь в Бикини Боттом, свободная локация, иду к двери Сквидварда и говорю с ним». **№2 и №3 — вслепую:** пользователь говорит их только после заморозки кода. Метрики: время от фразы до сцены; можно дойти до цели; NPC держит характер ≥ 10 реплик; судья 1–5 «это то, что я придумал» | все 3 идеи собраны без правки кода и промптов; оценка ≥ 3.5 на слепых №2–3; сцена готова ≤ 5 мин (ритуал засыпания) | библия мира грубее (шаблоны локаций + слоты), больше проходов самопроверки |

| H3 | Wonder стабильно вызывает инструменты по схеме | 20 тиков на demo day | ≥ 90% валидных, ≤ 8 с на тик | режиссёр на Spark max |

### Идеи (Oct 27, после H7/H8) — приняты

**1. Небо и пол у каждой сцены.** Без них объекты висят в пустоте.
- Небо — equirectangular-панорама 2:1 на сфере вокруг игрока (`scene.background`). Варианты: Skybox AI (Blockade Labs, сделан под 360°) или GPT image + заделка шва и полюсов. Сравнить оба (H13).
- Пол — бесшовная тайловая текстура («seamless tileable»), `RepeatWrapping` + туман к горизонту, чтобы не было видно края карты.
- Держим в голове: World Labs (авторы Spark) генерит целое окружение сплатами. Ещё одна зависимость — только если панорама + пол не вытянут.

**2. Карта сцены: директор планирует раскладку сверху.** Планировщику хватает 2D: объекты стоят на земле → x, z, поворот, размер. 3D нужно только для «поставить на / подвесить».
- Директор выдаёт план JSON: объекты, позиции, размеры, точка спавна, главный объект.
- **LLM предлагает, код проверяет:** пересечения футпринтов (размер известен точно — SAM3D отдаёт единичный куб, масштаб наш), свободный проход, главный объект виден со спавна. Ошибка → директору возвращается список конфликтов.
- План рендерится в PNG сверху — для отладки, для видео и чтобы директор сам посмотрел (vision) и поправил.
- Сюда же нормализация ориентации SAM3D (из H6): «лицо» объекта к спавну.

**3. NPC тянет время, пока за дверью генерится сцена.** Классический приём игр (лифт в Mass Effect, щель в God of War) — прячем латенси генерации в геймплей. Закрывает провал живой генерации из H6.
- Генерация следующей сцены стартует **по приближению** к двери / NPC (prefetch), а не когда игрок постучал.
- NPC не пускает в образе: Сквидвард ищет ключи, ворчит, задаёт вопросы. Реплики-тики крутятся, пока очередь не скажет «готово».
- Готово → дверь открывается, переход через рассыпание (H8).
- Таймаут или ошибка генерации → за дверью предгенерированная сцена. Игрок разницы не видит.
- Нужно в движке: фоновая очередь генерации со статусом (`job_status`), который видят и NPC-актёр, и режиссёр.

**4. Голоса NPC: кастинг и клонирование через Fish Audio.** Всё доступно по API (проверено по докам):
- **Поиск в библиотеке:** `GET https://api.fish.audio/model` — фильтры `title`, `tag`, `language`, `sort_by=score|task_count`; у каждого голоса есть описание, теги, языки и сэмплы.
- **Мгновенное клонирование без модели:** в TTS-запросе вместо `reference_id` передать `references: [{audio, text}]` — голос по одному образцу прямо в генерации.
- **Постоянный клон:** `POST /model` (`type=tts`, `voices` = аудио, `texts` = расшифровки, `train_mode=fast` — готов почти сразу, `visibility=private`).
- **Как даём директору:** основной путь — **наш курированный каталог** на 30–50 голосов с тегами (пол, возраст, тембр, язык, характер). Голоса заранее прослушаны, `reference_id` стабильный, выбор мгновенный. Живой поиск по библиотеке — запасной путь, когда в каталоге нет подходящего: в публичной библиотеке много мусора, и поиск добавляет латенси. Инструмент `cast_voice(npc, description)` → `reference_id`.
- **Клонирование для сна из твоего дня:** голосовая заметка дня → `references` → во сне звучит голос самого пользователя (например, «внутренний голос» или двойник). ⚠️ Чужие голоса (друзья из заметки) — только с согласия; для сабмита клонируем только самого пользователя.
- **Известные персонажи уже есть в библиотеке:** `GET /model?title=squidward` → 88 голосов, топ — `549dc86f…` (15K использований), есть и испанский «Calamardo». Клонировать не нужно: директор ищет по имени персонажа и берёт самый популярный. Свой клон — по 10–30 с чистой речи персонажа, если в библиотеке нет.
- ⚠️ Персонажи и голоса Губки Боба — только для тестов. В сабмите и видео свои персонажи, без защищённых IP.

| curious (любопытный) | клюнул на **уровне 0** — хватило свечения полки | 4 / 5 |
| stubborn (только Гэри, обещал не трогать) | игнорировал всё → **уровень 4**, движок тянет сам | 4 / 5 |
| chatty (болтает про кларнет) | игнорировал всё → **уровень 4** | 2 / 5 («запрет на уровне 2 — как маркер квеста») |

- Дисциплина уровней идеальная: 0 упоминаний книги на уровнях 0–1, 0 взглядов на уровне 0, 0 утечек. Уровень 1 сам нашёл приём «nothing over there, nothing at all» — проговорка, а не указатель.
- **Запрет не сработал на моделях-игроках:** послушные персонажи отвечают «окей, не трогаю». Реальный человек скорее нарушит — проверять на людях. Вывод: **уровень 4 (движок тянет сам) обязателен**, без него 2 из 3 игроков застревают.
- Уровень 2 лучше вплетать в тему разговора (у chatty — «моя техника… не как в той книге»), а не голым запретом: судья снял балл именно за это.
- ⚠️ Мелочь: у curious один ход игрока пришёл как «O» (обрыв стрима), судья иногда возвращает пустой `content` (reasoning съел лимит) — добавлен ретрай.
- Данные: `h0/out/hint/{curious,stubborn,chatty}.json`.
