# Где LLM спотыкается — журнал трений → будущие инструменты

Правило журнала: пишем только то, что реально мешало в работе (с датой и случаем), и сразу — какой инструмент это снял бы.
Цель: движок и тулинг, в котором любой LLM работает без самодельных костылей. Связано с «Движок: LLM-native» в RESEARCH.md.

| # | Трение (что случилось) | Чего не хватило | Инструмент / практика |
|---|---|---|---|
| 1 | **Не видно результата 3D.** Чтобы посмотреть небо+пол, написал свой three.js-просмотрщик + Playwright; браузеры Playwright не скачаны → пришлось через системный Chrome (Oct 27, H13) | Одна команда «сними сцену с этих камер» | `scene.shot([{pos, look}], …)` → сетка картинок, headless, детерминированно; камеры по именам: spawn, wide, up, down, from_npc |
| 2 | **Нет канона у 3D-объекта.** SAM3D кладёт всё в единичный куб, Z вверх, «перед» у каждого свой → поворот и высоту подбираю по скриншотам (Oct 27, сцена Conch Street) | Метаданные объекта | Сайдкар `<obj>.meta.json`: `up`, `front_yaw`, `height_m`, `footprint`, `pivot=bottom`. `front_yaw` авто: рендер с 4 сторон → vision выбирает «лицо» |
| 3 | **Метрика врёт, глаз нет.** Шов песка по числу 3.6 («виден»), а в тайле 3×3 стыков нет; edit «убери шов» число почти не меняет (Oct 27, H13) | Проверка в контексте использования | Проверять так, как увидит игрок: тайл 3×3, сфера, вид из шлема → vision-оценка; числа — только грубый гейт |
| 4 | **Возможности API не описаны.** Пробами выяснял: `size` есть (2048x1024 → 2240×1120), `aspect_ratio` нет, `mask` в edits нет (Oct 27) | Справка «что реально принимает endpoint» | `api_probe` раз в день → `capabilities.json` (параметры, ошибки, реальные размеры); LLM читает её до вызова |
| 5 | **Модель редактирования сохраняет дефект.** «Убери шов» → шов остался; «дорисуй серую полосу» → сработало (Oct 27) | Инпейнт без маски как готовая функция | `inpaint(image, region)`: залить область нейтральным → edit «заполни серое» → вклеить с растушёвкой. Один вызов вместо трюка |
| 6 | **Бенч шумит.** Fish каждый прогон генерит новый дубль TTS → сравнение режимов ASR зашумлено (Oct 27, H10) | Фикстуры | Кэш тестового аудио/картинок по хешу промпта; бенч гоняет одни и те же байты |
| 7 | **Нет диффа.** Проект не в git → «что я поменял» только через ручной бэкап (Oct 27) | Снимок до/после | `git init` в проекте с первого дня (или авто-снапшот перед каждой правкой агента) |
| 8 | **Долгие GPU-задачи вслепую.** Modal SAM3D: ни прогресса, ни ETA — только «ждать уведомления» (Oct 26–27) | Статус задач | Очередь с `job_status` (уже нужна для двери Сквидварда) — один формат и для движка, и для разработки |
| 9 | **Контекст теряется при сжатии.** Решения выживают, только если записаны на диск (RESEARCH.md спас) | Журнал решений | Каждое решение и замер — сразу в файл, с цифрами и путём к артефакту; сессия = журнал, а не память чата |
| 10 | **Шаблонный мусор неясен.** В IWSDK-стартере робот, панель, студия — непонятно, что безопасно удалить (Oct 27) | Карта зависимостей | `scene.describe()` + «кто импортирует что» одной командой |
| 11 | **Масштаб угадываю.** «Дом ~5 м, Сквидвард ~1.8 м» — из головы, не из данных (Oct 27) | Размеры из библии | LLM-библия мира отдаёт `height_m` каждому объекту; раскладка берёт оттуда |
| 12 | **Оболочка без нутра.** SAM3D-дом — сплошная оболочка; на вопрос «а интерьер?» нет ответа из данных (Oct 27) | Знание, что у объекта есть «внутри» | В `meta.json`: `enterable: false`, `portal_to: <location>`; движок сам предлагает дверь-портал |
| 13 | **Замер fps зависит от среды, а не от сцены.** Ноут на батарее 17% → браузер режет до 30 fps даже на пустой сцене; агент полчаса крутил бюджет LoD впустую (Oct 27) | Проверка окружения перед замером | `perf_preflight`: питание, energy saver, vsync, температура — до любого fps-теста; результат пишется рядом с числом |
| 14 | **Скриншот сам роняет fps.** Каждый замер делался скриншотом → провал кадра попадает в HUD (Oct 27) | Замер без наблюдателя | fps-лог из цикла мира за N секунд в файл, скриншот — отдельно и после |
| 15 | **Классификатор прав запретил удалить мёртвые файлы шаблона** — агенту нужна явная политика «что можно удалять» (Oct 27) | Разрешение на чистку в рамках задачи | В контракте задачи — явный список удаляемых путей, утверждённый человеком заранее |
| 16 | **Не нашёл существующий трекинг.** Завёл `PROGRESS.md`, не проверив, какие файлы прогресса уже ведутся; пользователь: «файлы прогресса есть… надо нормально всё трекать» (Oct 27) | Один вход в состояние проекта | Единый `PROGRESS.md` с картой «какой файл за что отвечает»; агент читает его первым и обновляет после каждого шага |
| 17 | **Reasoning-модель возвращает `content: null`.** Судья H17 упал: reasoning съел весь `max_tokens` (Oct 27) | Защита от пустого ответа по умолчанию | Обёртка LLM-вызова: `content or ""` + ретрай с бо́льшим лимитом, в одном месте, а не в каждом тесте |
| 18 | **Запустил исполнителя без согласованной спеки.** На большую работу (весь 2D-каркас) сразу отправил агента по контракту в чате; пользователь остановил: «напиши план спеку работы» (Oct 27) | Точка согласования перед дорогой работой | Для работ «весь каркас / несколько часов агента»: сначала `specs/<дата>-<тема>.md` с планом, открытыми вопросами и оценкой → «ок» пользователя → только потом tero |
| 19 | **Агентный CLI-критик молча висит.** `opencode run` с GLM 5.3 Flash (free) >20 мин, stdout пустой, stderr пустой — не понять, думает он или застрял; пользователь велел убить (Oct 27) | Видимость прогресса у фоновых моделей | Критиков звать прямым API-вызовом с контекстом в промпте + таймаут; агентный CLI — только со стримом прогресса в лог |
