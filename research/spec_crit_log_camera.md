# Лог критики спеки camera-moves (11-02)

Критик: codex gpt-6-luna, три линзы (1 — соответствие репозиторию, 2 — однозначность и проверяемость, 3 — достигает ли цели хозяина). Хозяин попросил 10 раундов с моими правками.

Оценки по раундам: 1: 4/4/4, 2: 4/4/4, 3: 4/5/4, 4: 6/5/4, 5: 4/4/6, 6: 5/5/4, 7: 5/5/4, 8: 5/5/5, 9: 6/5/5, 10: 5/5/6. Потолок держится на 5–6: каждый раунд закрывает дыры и открывает новые мелкие, 10/10 не достигнут.

## Что принято (сверено с кодом)
- Архитектура: Spark выбирает ИМЯ приёма, код считает точки; три реестра `MOVES` / `SCHEMES` / `RECORDS`.
- Законность пути: пробы + расстояние отрезка до каждого ребра ≥ `0,3 + 1,5·shake`, высота с запасом; `resolveMove` не выдаёт `cut: true`; fail closed (`MOVE_NO_LEGAL_POINT`, `MOVE_OCCLUDED` не попадают в `plan.json`).
- 180°: `pairSide` (исходная сторона, порог 90° из кода) и отдельный `flipForFaces`; лицо по `faceDir` (`faceYaw ?? yaw`), для лежащих отдельные правила.
- Одно определение «движения» (0,1 м / 2° fov / 5° взгляда) в К1, К2, приёмке.
- Источники тегов `first/enter/look/last`, `beat`, `room`; порядок `last` относительно `shots.end`.
- К3: `camera_style` по всей цепочке, `actors_by_beat`, тайминг `at/to` кодом, схема `notes`, `back_frames` и `shots()` по `dcut` в `critic.py`.
- Приёмка блокирует SHIP: пороги для трёх стилей, контакт-листы на одних битах.

## Отклонено / оставлено открытым
- Покадровая защита от затылка в планах Spark: рантайм их не перепланирует, это ограничение первой версии; ловит приёмка по `back_frames`.
- Сопровождение по реальному маршруту актёра: первая версия — только прямой маршрут, иначе статика.
- Допуск сегмент–сегмент и точная синхронизация часов теста с `ShotClock` — решит игрок в тестах.
- Визуальная различимость пяти стилей вне трёх приёмочных — только машинный тест различимости.
