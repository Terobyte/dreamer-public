# Лог критики спеки engine-xr

Критик luna (codex gpt-6-luna, read-only), правки мои. Линзы раунда: a, b.

## Раунд 1 → 0.2 (a: соответствие репозиторию; b: исполнимость в IWSDK)
Оценки luna: 4/10, 4/10. Принято всё (сверено с кодом): `style` без `tone/exposure` в типе; границы `buildWorld` (двери внутри, bridge/stage в `main.ts`, `geo/nav/layers` в мире); источник `hide`; ключ `dreamer.world` без миграции, поля отчёта; `setCells` не обновляет физику локомотора, забор статичный, двери kinematic без клеток в заборе; телепорт не спрашивает нав → однократная сверка после скачка; pinch не доказан, реальный путь — swipe up (кнопка 7) и микрожесты; невидимые меши берутся (F12); капсула IWSDK 0.5 м против 0.25 м нава → забор со сдвигом (F11); `door_touch` (DOM) против `touch` (сим) — два утверждения; `camera: null` требует режима в `stage/index.ts`; `browser profile` не измеряет Quest, лимита draw calls нет; `xr set-transform` в XR-origin.

## Раунд 2 → 0.3 (a: тестируемость; b: порядок и риск)
Оценки luna: см. выше (в выводе оценка обрезана). Принято: X1 после сабмита 4 ноября с эталоном `shots` до правок; состав `root` и тест по `id`; формат и алгоритм `buildFence` только из bitmap и `nav.doors`, `insetM = 0.5`; обёртка `teleport` вместо порога скачка; poke в долг, приоритет системы дверей раньше локомотора; фикстура двери и заглушка sim; схема отчёта, таймауты и коды `xr-check.mjs`; интерфейс `StageView` и измеримые тесты X5, X5 помечен как может не успеть. Не принято: короткий тест на Quest после X2 — шлема нет, пункт в X6/железо.

## Раунд 3 → 0.4 (a: противоречия и ссылки; b: достигает ли цели)
Оценки luna: 4/10, 4/10 (раунд 2: 3/10, 4/10). Принято: `tone/exposure` сборка вообще не пишет (`geometry.ts:310`) → константы в `world.ts`, схему не трогаем; загрузчики подставляются, «без DOM» уточнено; телепорт проверяется на текущем этаже, цель до локомотора не доходит; исключение для `import three` в `engine-host.ts`; открытие двери в тесте через `__dreamerXr.openDoor`, нажатие — система по `Pressed`; ширина — поле `width`, высота капсулы 2.0 м против 1.8 нава; тени и outdoor в контракте `buildWorld`; регрессия десктопа перечислена; вход/выход XR и оркестрация `npm run xr:check`; минимум VR Start = X1–X4, телепорт/руки → X3б необязательный, X5 после минимума; цель fps Quest. Не принято: звук реплик в обязательном этапе (X5 вне минимума).

## Раунд 4 → 0.5 (a: исполнимость для tero и преамбула; b: красная команда)
Принято: `addOutdoor` возвращает `{objects, background}`; загрузчики и `base` для scatter и outdoor; гарантия vitest ограничена фикстурой без outdoor/scatter; `built` необязателен; `loads` в мире; `build.json` и `package.json` в X2; **найден баг спайка**: `createTransformEntity` переподчиняет оболочку активному уровню (`world.js:176–179`) → `{ parent: rootEntity }`; `oneThree` по объектам из `buildWorld`; край сетки нава непроходим; рампы в маске забора; ширина двери из `built.doors`; приоритет ELICS по возрастанию числа, система дверей < −5; фронт `Pressed`, а не опрос; позиционный звук через буфер вместо `new Audio`.

## Раунд 5 → 1.0 (a: финальная проверка исполнителем; b: ссылки)
Оценки luna: 5/10, 6/10. Принято: единая сигнатура `buildWorld` (`built?`, `loaders` с отдельным `scatter`); поле `error` в отчёте и код 4; приёмка «без дрожания» (0 вызовов `setPlayerPosition`, нет смены знака смещения); дверь в тесте сначала закрывается (`doorDefs` открывает по умолчанию); рампа — по `rampWalkable`, не весь полигон; мировая поза камеры в X5, кадр для фильма отдельно от позы головы; `scene_get_render_stats` вместо метрик `browser profile`; прямой `import three` убран — `oneThree` по классам `@iwsdk/core`; ссылки `main.ts:135–138`, `build/doors.ts:164`, `build/write.ts:361`.
Итог: 5 раундов, оценки luna 4/4, 3/4, 4/4, (раунд 4 не снимал), 5/6. Не 10/10: цель раундов — снять расхождения с кодом, а не довести оценку; остаток — неподтверждаемое без железа (fps Quest, телепорт, руки).
